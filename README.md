## 环境与构建

需要 Ubuntu 22.04、ROS 2 Humble、Python 3.10、colcon、编译工具和 `requirements.txt` 中依赖；相机、厂家 SDK、Fast-FoundationStereo、GraspGen-X 和 GPU 权重需独立安装及配置。实际现场标定不包含在此项目。Python 依赖应安装到与 ROS Python 3.10 兼容的环境；例如在隔离环境中安装 `python -m pip install -r requirements.txt`，ROS Python 包也需在该环境可见。

```bash
cd /home/ubuntu22/nero_conveyor_ros2
source /opt/ros/humble/setup.bash
colcon build
source install/setup.bash
ros2 interface show nero_interfaces/msg/TimedTrajectory
ros2 launch nero_bringup offline.launch.py
```

本机 ROS 代码生成器在包含中文字符的工作区路径下失败，因此工作区位于英文路径。launch 输出为人工构造的检测、认证、跟随闭合、夹持确认、抬升、投放和回位事件，证明事件状态转换，**没有计算抓姿/轨迹，没有物理碰撞或夹持**。

脱离 ROS 的测试（激活含依赖的 Python 环境后）：

```bash
cd /home/ubuntu22/nero_conveyor_ros2
PYTHONPATH=src/nero_core:src/nero_bringup MUJOCO_GL=egl OPENBLAS_NUM_THREADS=1 python -m pytest -q
```

这里的 `MUJOCO_GL=egl` 供旧模块中的无窗口测试使用，不启动机械臂或相机。旧项目的测试夹具 `fixture_single_pick.py` 被导入但不单独收集，因其中部分旧测试需要本次未迁移的旧命令行入口。更多依赖及具体限制见报告。

## 现场配置与时间

配置模板在 [site.template.yaml](src/nero_bringup/config/site.template.yaml)。工作区、抓取区间、现场等待姿态、料箱及物理 TCP 等必须使用现场可靠数据；两秒入口使用单独的 [真机模板](src/nero_bringup/config/two_second.hardware.template.yaml)，通过 `two_second_pick --check-config` 读取和验证；未知类别规则也必须明确配置。数值坐标以标定基座系、米、弧度和秒为单位。旧工程的相机标定、历史传送带方向及设备配置已整理为[现场候选及来源核对](docs/旧项目现场配置核对.md)，待确认是否仍适用于当前现场；用户已确认夹爪与旧模型一致，旧项目名义 TCP 已接入，并保留模型来源。

接口预留曝光 ROS 时间、主机接收时间、单调时间、设备时间和时钟代次；不同时间域不能直接相减，设备时间必须通过经验证的转换映射，ROS 仿真时间暂停或跳变时需要中止旧任务和重新建立映射。**新 ROS 时间转换和重置处理尚未接线**。原 `feedback_clock.py` 的代码和测试已迁入，但不等于完整 ROS 时钟方案已完成。
