# 碰撞定位与同源相机预览

真机两秒入口现在可记录“机器人与实测工件点云碰撞”的精确触发状态，并复用原相机预览窗口。窗口增加只读跟随模式，直接消费抓取程序的相机帧、实际冻结OBB输入和碰撞快照，不再次开启相机、CAN或另一套检测/测速。

此前 `test_20261030_194457_057506762` 未保存目标点云、具体碰撞几何和原始曝光，无法事后补回这些数据。本轮展示与验证使用明确标记的合成输入，不是对该次现场失败的碰撞复现。

## 启动

原真机命令增加 `--preview` 即可同时打开窗口。执行前应退出旧预览的独立相机模式，使用以下共享模式，避免两个程序争用同一设备。

```bash
cd /home/ubuntu22/nero_conveyor_ros2
source /opt/ros/humble/setup.bash
source install/setup.bash

OPENBLAS_NUM_THREADS=1 ros2 run nero_core two_second_pick \
  --config /home/ubuntu22/nero_conveyor_ros2/install/nero_bringup/share/nero_bringup/config/two_second.hardware.legacy_observed.yaml \
  --execute --preview --count 1 \
  --output "/home/ubuntu22/nero_conveyor_ros2/runs/two_second_hardware/test_$(date +%Y%m%d_%H%M%S_%N)"
```

`--preview` 自身不授权执行；省略 `--execute` 仍只检查配置，不打开设备或窗口。ROS launch 对应 `preview:=true`。显示端另需 PyQt5，可安装 `requirements-preview.txt`，或安装包的 `preview` 可选依赖；不显示窗口时核心算法不要求PyQt5。

运行中也可以单独打开只读窗口，或在结束后重新查看同一个目录：

```bash
ros2 run nero_core camera_grasp_view \
  --config /home/ubuntu22/nero_conveyor_ros2/install/nero_bringup/share/nero_bringup/config/two_second.hardware.legacy_observed.yaml \
  --follow-run /home/ubuntu22/nero_conveyor_ros2/runs/two_second_hardware/本次目录
```

原 `tools/view_live_grasp.py` 路径继续可用，现为已安装模块的兼容入口。其独立相机/历史曝光模式保留；使用 `--follow-run` 时禁止同时指定只读CAN或独立曝光回放选项。共享窗口没有使能、运动或夹爪控制。关闭窗口只关闭显示；停止抓取仍在抓取终端按Ctrl+C。

## 画面含义

- 左上：抓取程序共享的实时RGB；程序结束后标记为历史画面，超过新鲜度要求会提示过期。
- 左下：抓取程序实际冻结的OBB输入；有碰撞记录时显示对应原始曝光与预测叠加。RGB投影使用该曝光的深度到基座标定、实际深度到彩色外参、彩色内参及畸变，不使用最新帧标定替换旧记录。
- 右侧：基座系点云及被拒绝姿态下的机器人网格。青色为预测时刻被检查的工件点云，紫色为曝光点云，红点为触发拒绝的点，橙色为对应机器人凸包，黄色为原4毫米碰撞余量的半空间包络。
- 下面列出碰撞几何/机器人部件、规划候选与原始输入抓姿序号、目标ID、曝光序号、轨迹时刻，以及原凸包内部/仅余量内的点数。可选历史碰撞记录、拖动旋转、滚轮缩放或聚焦碰撞。

机器人网格和红点是规划预测，不代表相机已经拍到了撞击。碰撞记录固定绑定其原始曝光、时钟代次、任务目标及轨迹版本；实时相机转入下一帧或时钟代次不会把旧碰撞重投影到新曝光。窗口仅显示诊断，不能授权执行或覆盖控制状态。

## 记录内容与判定

每个触发拒绝的采样状态保存于 `本次目录/collisions/collision_XXXX.*`：

| 文件 | 内容 |
|---|---|
| `.json` | 碰撞几何名称/ID、部件名称、是否手指、4毫米余量、触发点数、首点、点与凸包半空间关系、接触是否允许、q/TCP/开口、实际采样时刻、候选、目标/版本/场景修订、曝光时间和标定信息 |
| `.npz` | 全量曝光点云、预测检查点云、触发索引和全部触发点、原始RGB/深度、原机器人网格/位姿及凸包半空间、用于显示的机器人和余量包络线段、实测过滤场景 |
| `.png` | 原曝光上的碰撞预测投影；明确标记预测，原始RGB仍保存在二进制包内 |

点与凸包关系来自原碰撞测试使用的同一半空间方程：最大平面值≤0为本体内，0到4毫米为仅进入余量范围。该数值不是精确的欧氏穿透深度，也不能仅凭“余量内”断言现场无碰撞。允许接触阶段的手指豁免与原4毫米判定、碰撞覆盖、200Hz采样和发送截止均保留。

本轮完整快照针对 `MeasuredPlanner.valid` 中机器人—工件点云检查，包含该分支的载物状态。自碰撞、带面、机器人—障碍场景、载物—场景等其他拒绝仍沿用原有错误与上下文，并未全部获得相同的三件套快照。

## 线程、存储与终端

抓取视觉线程只把已有不可变帧引用交给后台；共享画面最多约5Hz，`preview/latest.npz` 原子替换，不连续积累图片。冻结目标同样复用生产结果，`preview/target.npz` 保存实际输入，不另跑预览检测器。图像、深度和点云通过二进制文件传递，不编码成JSON数组。

碰撞发生时才冻结数组与机器人几何；凸包显示线段生成、RGB投影和写盘在有界队列后台执行。其错误单独记入 `summary.json.visualization` 和 `collision_diagnostic_errors`，不能改变碰撞拒绝或许可运动。队列满会报告丢弃数；后台关闭仍未完成会报告 `writer_alive`，不伪称证据已保存。

终端仍是简短步骤；每个碰撞仅增加一行，例如 `[碰撞] left_finger_geom，轨迹 1.050 s；记录 collision_0001`。完整事件见 `collision_detected`/`collision_saved`；GUI自身错误写入 `preview/viewer.log`。`visualization.write_wall_s` 是后台归档处理耗时，`visualization_shutdown_wall_s` 是退出等待后台的耗时，不应再与重叠的规划耗时相加。

## 离线验证边界

验证包括已知凸包内/4毫米余量内点、原手指接触豁免、诊断失败仍拒绝路径、全量二进制回放、带相机旋转/平移及彩色外参的投影、旧曝光与新时钟代次隔离、冻结OBB同源共享、只读窗口持续刷新和退出。另用原机器人模型的 `left_finger_geom` 与合成测试点验证完整保存和显示；Qt窗口截图明确标记“离线合成验证”。

本轮没有连接相机、机械臂或CAN，没有发送真机命令；没有据此验证现场碰撞真假或完成物理抓取。真实相机与抓取并行时的现场性能、标定误差和实际失败位置，须由后续运行生成的新记录确认。

验证记录：`runs/collision_visuals_20261030_195513/`。383项离线回归通过；`nero_core`/`nero_bringup` 构建通过，源码与安装副本检查通过；安装入口的只读Qt回放、截图和正常退出通过。合成点云的触发几何为原模型的 `left_finger_geom`，不代表上一次现场失败也发生在该部位。
