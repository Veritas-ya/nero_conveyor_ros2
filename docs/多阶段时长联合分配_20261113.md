# 固定作业空间下的多阶段时长联合分配

本轮实现可选 `phase_timing` 模式：联合搜索接近、闭爪后同速跟随、减速三个时长。
未修改现场 YAML、等待关节姿态、抓取区间、工作空间、原关节限值或 90 ms 提前量。
新模式缺省关闭；本轮没有连接相机/CAN，没有执行机械臂或部署安装目录。

## 决策和现有执行语义

- `join_s`：由静止接入目标同向同速运动的平移时长；原有独立预转时间仍单独计入。
- `follow_s`：参考接触时刻触发闭爪之后的同速跟随时长。
- `brake_s`：同速跟随结束后降到静止的时长。
- 原 `synchronized_duration_s` 是闭爪指令**之前**的同速段。本版保留该设置，不把它算作闭合时间，也不把 90 ms 指令提前量算作额外夹持时间。

第一版支持 `smooth + synchronized + scheduled_attempt`；不支持独立预转时间自动重定时，
也不与 `execution_delay_window` 同时启用，以避免重复计算时延余量。
本轮三阶段分配不是原论文工具 `timing_experiment` 的 A/B/C 分组，不应混用名称或统计。

## 算法

1. 读取显式有限候选网格，最多 256 个时长组合，最多两个原有短轴对称抓姿。
2. 对每组抓姿和时长重新预测接入时间、接触位置和停止位置。等待位、工件点云、抓姿来源及边界保持原值。
3. 检查闭爪后时间窗口、同步/跟随区间、停止投影区间、三维工作空间和 TCP 加速度上界。
4. 将各约束余量按其特征尺度归一化，取最小值作为参考轨迹余量分数；同分时优先较早完成。
5. 按“接近时长＋抓姿”分组轮换尝试：每组先尝试其最高分候选，再尝试组内下一项，防止同一过短接近的多种跟随/减速组合耗尽预算。
6. 每次完整尝试重新计算当前时钟下的目标位置并复核约束，沿用原 IK、关节多项式极值、几何/TCP 参考、发送截止和总规划预算检查。返回首个完全通过原检查的候选。
7. 保存选定时长、约束余量、网格排除原因及配置/参考绑定摘要。执行准备和发送入口都复核绑定。

这是**有界离散搜索和首个可行候选策略**，没有全局最优、成功概率最优或物理抓取保证。
关节状态的作用由现有模型、IK 和完整曲线认证体现，初筛的 TCP 加速度约束不能代替关节限制。
参考余量排序也不是物理成功率预测器。

## 约束含义

标称模式要求闭爪后跟随时长至少为：

`gripper_close_time_s + 原有 0.2 s 夹持确认驻留时间 + 一个控制周期`。

鲁棒实验模式另加 `gripper_time_margin_s + residual_time_bound_s`。
这是保守的规划窗口要求，现有实际夹持确认和抬升门槛仍保留。
它不能证明已经抓住工件，也不能把失败强行改成成功。

`residual_time_bound_s` 是已经考虑固定提前量之后的**剩余时间误差半宽**，不是约 85–90 ms 的绝对关节等效滞后；不得再次减去提前量。
空间余量采用沿带 `v * residual_time_bound_s + position_margin_m`，三维工作空间逐坐标使用相应速度分量。

现有减速曲线的停止位移为 `velocity * brake_s / 2`，TCP 加速度峰值为 `1.5 * ||velocity|| / brake_s`。
接近段使用多项式导数的内部驻点和端点求逐坐标极值，构造保守的加速度范数上界；不只检查端点或稀疏采样。
停止区间与抓取区间是两个独立概念。本轮配置副本保守地将停止投影也限制到原抓取区间 `[-0.20, 0.38] m`，
并继续检查原三维工作空间；这不是对现场可用停止空间的新测量。

尚无摩擦、接触力、闭爪实际运动或执行偏差扫掠体模型。因此不能声称无滑移、鲁棒碰撞认证或实物成功率提升。

## 离线参数和执行边界

`outputs/phase_timing_20261113/spec_assumed_offline.json` 明确记录了以下设计假设：

| 参数 | 数值 | 证据状态 |
|---|---:|---|
| 接近候选 | 0.6 / 0.8 / 1.0 / 1.1 / 1.3 s | 离散搜索网格 |
| 闭爪后跟随候选 | 0.32 / 0.40 / 0.50 s | 离散搜索网格 |
| 减速候选 | 0.4 / 0.6 / 0.9 / 1.2 s | 离散搜索网格 |
| 闭爪时间 | 0.10 s | 尚未实测 |
| 额外闭爪时间余量 | 0.04 s | 尚未标定 |
| 剩余时间误差半宽 | 0.015 s | 假设值，不是统计置信界 |
| 额外位置余量 | 0.003 m | 假设值 |
| TCP 加速度上限 | 4 m/s² | 设计约束，不是已验证的防滑上限 |

所有新模式副本均标记 `calibration_status: assumed_offline`，可用于规划回放，实际计划执行入口会拒绝。
后续必须补充夹持时间、带速/跟踪误差和减速稳定性证据，才能将实验配置用于上机验证。
将字符串改为 `measured` 本身不产生标定证据，不构成物理性能验证。

## 离线工具

在仓库根目录执行，使用系统 Python；无 SDK 或设备入口：

```bash
PYTHONPATH=src/nero_core OPENBLAS_NUM_THREADS=1 python3 tools/phase_timing_experiment.py prepare \
  --base src/nero_bringup/config/two_second.hardware.legacy_observed.yaml \
  --spec outputs/phase_timing_20261113/spec_assumed_offline.json \
  --output /tmp/nero_phase_timing_new_session \
  --fixed-times 1.1 0.4 0.9

PYTHONPATH=src/nero_core OPENBLAS_NUM_THREADS=1 python3 tools/phase_timing_experiment.py replay \
  --configs /tmp/nero_phase_timing_new_session \
  --run runs/control_panel/pick_20261113_110415_884109 \
  --output /tmp/nero_phase_timing_new_replay.json
```

输出目录/报告已存在时拒绝覆盖。配置、输入文件、源码均记录哈希；源码在回放中变化会显式记录。
`current` 是原设置副本；`fixed` 是显式给定时长的示例对照，**没有经过调优**；`nominal`、`robust` 是新模式。
各组记录目标、速度、原始曝光到提交的年龄、提交时关节状态相同；不移动历史目标或重置其时间来制造可行结果。
跟踪冻结与单帧冻结使用各自的入口配置。早期错用跟踪配置回放单帧日志的结果保留作诊断，不纳入最终配对比较。

回放只重建每个 run 最后一个冻结点云，不等于回放该 run 全部抓取次数。
历史提交关节状态跨 run 可以不同，但同输入各组完全相同；不是一次固定姿态连续投放的正式实验。
配置使用本轮保存的现场副本，模型法兰由关节计算，夹爪假定打开，环境只重建原生带面点。

## 验证结果与下一步

汇总报告位于 `outputs/phase_timing_20261113/离线验证报告.md`。
其中分别列出解析参考测试、真实点云完整规划、失败原因和回归测试，不能把这些结果合并为抓取成功率。
首次真实回放已发现短接近候选的重复尝试耗时，已增加分组轮换；仍存在关节限制和剩余空间不足的拒绝。
现场 YAML、标定文件和示教文件的前后哈希在 `protected_before.json` 和 `verification_manifest.json` 中保存。

下一步先测闭爪到稳定夹持的时间及波动、确定允许停止空间和减速稳定性，再冻结实验参数进行少量上机测试。
现有离线结果不能证明新模式优于经过调优的固定时长方案。
