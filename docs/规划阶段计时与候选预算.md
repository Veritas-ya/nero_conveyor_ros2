# 规划阶段计时与单候选预算

2026-10-29 已实现并在 MuJoCo 中验证。控制器仍为 `full_preplanned`；保持 RGB-D/Nero7 测速和 OBB 抓姿实验来源，未接硬件。

## 运行行为

- `AsyncPlanningWorker.set_candidate_wall_budget(seconds)` 设置单个请求的协作取消预算；默认 `None` 保持既有调用方行为。实验入口默认读取 `control.candidate_planning_wall_budget_s: 3.0`，可用 `--candidate-wall-budget-s` 覆盖。
- 预算以工作线程开始执行后的主机单调时间计，覆盖整个规划请求。它与 `--compute-budget-s` 的策略时钟排期预留不同，不移动轨迹时钟、不暂停传送带。
- 同一个取消检查贯穿已有 IK、路径搜索和认证。超时结果明确标为 `planning_candidate_budget_exceeded`；即使一个耗时操作迟到后返回成功，也清除路径与认证标志。协作取消不是硬实时抢占：记录取消到工作线程确认结束的延迟。
- 只有尚未发送机械臂命令、没有活动执行轨迹、身份和观测有效、剩余窗口足够时，才允许因预算超时切换候选。旧上下文和工作线程必须停止后才建立下一上下文；每个新候选重新绑定抓姿、场景并规划认证。
- 重建会保留原有跟踪选项：显式冻结视觉实验保持自己的冻结设置，普通实时视觉仍保留原来的观测过期规则。

## 日志

结果文件旁新增同名 `.planning.jsonl`，主循环约每 0.25 墙钟秒写入阶段快照、增量阶段事件、拒绝计数和 IK 计数。即使还没有规划结果，也能看到运行中的阶段；不会同步保存图像或大数组。使用 `tail -f runs/visualization/obb_candidate_budget_final.planning.jsonl` 查看。

最终 JSON 的 `planning_runs` 保留每个候选的来源索引、输入、独立结果、取消阶段、墙钟时间、工作线程 CPU 时间、重试窗口与停止确认。阶段计时分为 inclusive（包含子阶段）和 exclusive（扣除子阶段）。只能将 exclusive 列相加，不能把父阶段和子阶段重复相加；墙钟与 CPU 时间也不能相加。

覆盖的阶段包括：逆解、关节路线搜索、笛卡尔分支探测、时间参数化、接近/下降/闭合/抬升曲线认证、批量场景验证、逐状态约束和碰撞检查、连续段认证器初始化、命令补偿和交付重排。高频状态检查只累计计时，不逐项写事件。

## 本次实测

`runs/visualization/obb_candidate_budget_final.json` 与同名 `.planning.jsonl`：使用中心线上方 20 cm 的仿真初始等待位，显式冻结视觉；此前要求关闭的雅可比条件数和 TCP 速度上限继续关闭。仿真执行器命令范围与 0.055 rad 关节余量、碰撞和时间窗口检查仍生效。

| 指标 | OBB 候选 1 | OBB 候选 2 |
|---|---:|---:|
| 总墙钟时间 | 3.009 s | 3.014 s |
| 逆解累计时间 | 0.009 s | 0.017 s |
| 逆解成功/尝试 | 4/4 | 4/4 |
| 接近曲线认证（含子阶段） | 2.666 s | 2.646 s |
| 连续段认证器初始化（不含子阶段） | 1.928 s | 1.950 s |
| 认证器初始化调用数 | 193 | 256 |
| 逐状态约束/碰撞检查 | 0.424 s | 0.464 s |
| 预算到取消确认延迟 | 5.2 ms | 13.5 ms |
| 重试前旧工作线程已退出 | 是 | 是 |

结果：两个候选确实分别启动了完整规划，预算达到后均退出；最终为 `candidate_planning_budgets_exhausted`，发送命令 0 条，没有夹持、抬升或投放成功。不能用“预算内没完成”证明不存在可行路径。

这次可确认的热点是连续段认证器反复初始化，位于逐时刻接近曲线认证中。初始化包含请求相关的碰撞快照、运动界限和认证结构，不能直接跨时刻复用碰撞结论。另一个明确现象是：批量接近检查已记录关节余量失败，随后仍进入逐时刻回退。候选 1 的第 1 轴余量 0.054805 rad、候选 2 的第 6 轴余量 0.054878 rad，均低于 0.055 rad。该次输入的冻结视觉 X 速度约 0.07459 m/s；并非与较早每次实验完全相同的观测，不能据此给过去所有运行重新判因。

后续优化应优先复用与模型/固定夹爪相关、确实不随请求时刻变化的认证准备，并对已经确认的时间无关约束失败及时返回。仍须保留逐请求工件/场景身份和版本，不跨观测复用碰撞认证。

## 启动

在已经装好 MuJoCo 等依赖的 Python 环境中：

```bash
cd /home/ubuntu22/nero_conveyor_ros2
PYTHONPATH=src/nero_core:src/nero_bringup MUJOCO_GL=egl OPENBLAS_NUM_THREADS=1 \
python tools/probe_measured_network_scene.py \
  --output runs/visualization/obb_candidate_budget_final.json \
  --early-vision --standby-at-reset --grasp-source obb --execute-sim --freeze-visual \
  --compute-budget-s 2.7 --candidate-wall-budget-s 3.0 \
  --sim-disable-tcp-and-singularity-limits --seconds 30 --viewer --hold-viewer
```

实际本机运行使用已有依赖解释器；上述 `python` 需指向对应环境。该入口是冻结视觉、OBB、MuJoCo 诊断，不是网络抓姿闭环或实机入口。
