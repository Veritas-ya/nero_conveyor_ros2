# 多帧候选的带面高度分离

多帧跟踪入口 `two_second_pick` 的现场配置 `two_second.hardware.tracked_freeze.yaml` 启用了 `split_mixed_belt_candidates`。冻结之前，当工件和传送带高光在 RGB 掩码中连成一个候选、原来的深度高度占比会拒绝该候选时，使用同一帧的实测深度和带面高度，保留高度处于原检测器工件高度范围内的像素，再做连通域和原有 ID 关联。没有足够的实测工件高度证据时，不把不明深度当成工件，也不凭空填补深度。干净候选仍使用原来的处理。

分离仅作用于构建跟踪候选的临时图像；原始 RGB、深度、冻结抓姿点云和碰撞场景不由此修改。已冻结的目标继续使用原有的任务身份和冻结数据。单帧入口 `fixed_freeze_pick` 不使用此多帧 ID 关联流程，本次没有改变其检测逻辑。

使用 `runs/camera_track_diagnostic_20261113_2213` 保存的实拍 RGB-D，以及当时给定的固定带速 15.3 cm/s 回放，不连接相机或机械臂：

* 多帧冻结回放在第 614 帧得到目标及两组 OBB 候选；与之前同一帧的离线冻结结果比较，961 个目标点、抓姿矩阵、入口位置和速度数组均完全一致。结果在 `runs/diagnostics/depth_split_freeze_20261114/`。
* 合成测试覆盖高光连接、两个由带面连接的目标、普通候选、缺失深度和原始图像不变等情况。

该回放只证明所保存数据中的检测、关联及冻结数据交接；没有检验实时帧调度、真实关节反馈、路径规划或物理抓取。完全缺失目标有效深度、工件本身高度低于设定高度、遮挡或实际标定误差仍可能影响检测。
