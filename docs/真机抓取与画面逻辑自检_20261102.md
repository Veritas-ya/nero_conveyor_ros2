本轮没有打开相机、连接 CAN 或发送机械臂命令。`ros2 run nero_core two_second_pick --check-config` 返回 `configuration_valid`，连接和发送数均为 0。该检查只证明配置可以加载和 Python 依赖可发现，不能证明设备在线、标定正确或真机能成功抓取。核心抓取、恢复和预览代码的源码与 install 文件哈希一致；回归检查覆盖跟踪冻结、抓姿、轨迹、执行、异常恢复、身份切换、预览和故障替身。

当前真机配置使用 0.059 m/s 固定带速（除非启动命令覆盖），OBB 抓姿、2 s 同向接入、接入后闭爪前同速 0.2 s、闭爪跟随 0.8 s、减速 1.5 s、抬升 0.05 m；使用标称 TCP 而非现场实测 TCP。上位机指令差分加速度运行时阻断关闭，规划限值仍生效。自动回等待位已启用，配置报告该动作没有通过现场场景碰撞认证。并非所有仿真参数都与真实现场等同。

## 自检修复

恢复阶段的静止保持发送线程和恢复观察线程可能先后处理顺序不同的反馈快照，原来共享一份时间高水位会误报反馈时钟倒退。现在每个并发观察者使用自己的顺序记录，仍检测自身的时间倒退、时钟代次重置和过期反馈；修复同步至 install。新增确定性交错和真实时间倒退注入测试。全部所选 14 个测试文件最后一次运行 289 项通过；安装包路径下的恢复和预览相关测试 36 项通过。替身和注入不能证实真实机械臂表现。

在更早的重复真实线程测试中，出现过实际发送晚于该次几何检查约 10 ms 认证时间窗而拒绝执行的情况；之后 8 次独立循环通过。该限制没有放宽，问题仍需针对现场负载、CAN 延迟和控制发送线程做进一步观察，不能说所有条件下稳定。

## 同一仿真工件的抬升高度对照

实验均使用 0.059 m/s 固定速度、T-LESS 05、随机种子 2026；视觉位置和 OBB 来自模拟 RGB-D。仿真采用所列真机配置的软件参数，但相机、场景、等待位及机械臂伺服模型不是现场：开启仿真重力补偿和积分内环；载物使用仿真几何检查。每组只有一件，不能推断成功率。

- 配置默认抬升 0.05 m：检测、规划、闭爪和抬升后搬运失败，确认开口 0.05101 m，搬运时最大变化 0.00372 m，超过现有 0.003 m 判定。日志中出现工件与 `right_rail_downstream` 接触，工件相对夹爪最大位移 5.74 mm；停止前最大关节实际与参考偏差约 0.035 rad。RRT 碰撞检测确实检查过该侧边并拒绝了 10 个候选状态。执行跟踪偏差、工件相对位移和净空都可能有关，未证明单一因果。
- 仅将仿真抬升高度覆盖为 0.10 m：同一个物件完成夹持、抬升、稳定投放及返回；搬运期间观测到的工件相对夹爪最大位移约 1.65 mm，未记录工件与其他几何体接触。这只是仿真对照，没有修改真机抬升配置。

两组抓取规划峰值关节加速度均约 1.52 rad/s²，但 MuJoCo 2 ms 物理子步速度差峰值为 J6 约 46.0 rad/s²，出现在夹爪和工件接触期间。两者不是同一种测量；该仿真数值不是实机测量，仍说明模型及接触动态尚未完成验证，不足以证明真实系统满足 8 rad/s²。

实验数据：`runs/selfcheck_20261102/current_config_sim.json`、`runs/selfcheck_20261102/lift010_sim.json`。结论：软件离线链路和回放能够运行，但当前配置的单件物理仿真没有完整通过；真实设备连接、速度、标定、抓取成功与异常恢复均未在本轮验证。历史回放窗口只读，不代表现场实时画面。
