# 真机抓取逻辑自检（2026-10-30）

检查范围为当前 `two_second_pick / smooth` 真机入口，从自动回等待位、单相机 RGB-D、Nero7 XY 卡尔曼测速、OBB冻结、预测、规划到跟随闭合、夹持确认、抬升、固定料框投放、返回及取消。原项目未修改，本轮未连接真实相机、CAN 或机械臂，没有发送真机命令。

## 复现并修正的问题

| 问题 | 修正 | 离线证据 |
|---|---|---|
| 闭合确认起点使用发送前的夹爪反馈时间 | 记录实际闭合指令开始/完成时刻，确认只接受完成之后的新反馈，保留原0.4秒条件 | 注入20 ms发送耗时，旧逻辑确认起点早20 ms；修正后起点不早于发送完成 |
| 平滑抓取的张爪等待阶段没有持续关节保持发送 | 在上一条已认证轨迹静止终点维持同一个发送器，张爪确认后结束，再进入返回规划 | 原完整周期测试的静止发送阶段缺少release；修正后覆盖release；实际Python发送线程测试在张爪期间继续发送，成功、取消、反馈异常和张爪超时后均退出 |
| 载物静止保持用了全局参数，实际发送时缺少再次校验 | 准备、实际发送前校验、发送后记录都使用载物参数；张爪时保留载物运动参数，但不把主动张爪当成夹持丢失 | 注入准备时通过、延迟发送需3.333 rad/s²的情况，载物2请求在发送前拒绝，设备能力8保持 |
| NaN关节或开口可以绕过比较表达式，导致到位/张爪确认误通过 | 到位、张爪和夹持确认明确拒绝非有限反馈 | NaN到位/张爪测试在原代码上未抛异常，修正后拒绝 |
| 启动准备刚结束时取消，仍会继续创建相机 | 开启相机前增加取消检查，正常关闭已建立的连接 | 原入口故障注入测试确实创建了虚拟相机；修正后不创建 |

首组故障复现为5项失败（其中NaN分成2项），修正后5项通过。补充启动取消复现时为10通过、1失败，加入取消检查后通过。另加强CAN反馈时钟代次检查：即使映射后的单调时间仍递增，只要相关反馈的代次发生变化，也中止旧任务。它与相机时钟代次检查、原反馈新鲜度检查共同工作，不通过重写时间戳来维持任务。

关键源码为 `two_second/streaming.py`、`stationary_hold.py`、`release.py`、`feedback_gates.py`、`execution.py` 和 `main.py`。迁入副本 `runtime/single_pick.py` 的等待函数增加可选heartbeat，便于在张爪等待中及时检查保持发送器；旧调用默认行为保留。

## 保留的控制逻辑和参数

- 等待位和同框固定投放TCP位姿不变；没有将仿真真值料框选点导入真机。
- 每件冻结一次OBB抓姿与视觉速度，预测包括曝光至接触的全部时间。抓取方向/相对抓姿保持，执行中不因新帧改写目标。
- 优先2秒接近，候选时长仍为2、3、4、5.5、6.5秒；每个候选重新预测接触点并认证，交付后连续执行。
- 100 Hz发送、100 ms命令提前、0.8秒跟随和1.5秒减速不变。
- 厂家能力/全局加速度边界8 rad/s²，载物请求2 rad/s²，原2 N夹持、0.2 N受力门槛、3 mm开口变化保护、0.4秒夹持确认和关节到位0.005 rad/0.1秒条件不变。
- 张爪检查仍要求实际开口在原2 mm范围内稳定0.15秒，并新增必须晚于本次实际张爪命令的时间要求。

## 仍需现场或后续算法工作验证

1. **固定投放位可能堆高。** 前一轮物理仿真确实出现顶部超过框沿约50 mm；真机仍缺少料框容量/堆高的实际视觉确认。固定目标不能保证长期连续投放，当前程序只报告反馈周期完成，不声称真实入框成功。
2. **单侧接触工况尚未通用修复。** 前一轮随机姿态试验发生接近时手指提前碰物、闭合后单侧接触。它不是重新生成OBB造成的；当前仍依靠原反馈条件拒绝未确认夹持后的抬升，不能据此声称任意可见OBB都可物理抓牢。
3. **固定投放目标不保证每个抓取分支都可达。** 前一轮第五件在仿真空闲落点处没有得到目标逆解。真机需要从实际抓取后的关节状态生成并检查载物路线，不能因为等待位/投放位固定就跳过这一步。
4. **回位范围明确。** 启动回位沿用用户要求的厂家move_j平滑直达，不进行相机场景避障认证；它不代表任意起点都存在避障回位路径。
5. 夹爪宽度/受力只证明反馈条件满足；实际抬升和入框仍需现场独立观测。相机标定、厂家内环、延迟、摩擦和物件质量不能由仿真结果代替。

因此本次结论是已修正可离线复现的执行逻辑问题，并验证软件回归；不是对真机闭环成功率或任意工况无错误的保证。
