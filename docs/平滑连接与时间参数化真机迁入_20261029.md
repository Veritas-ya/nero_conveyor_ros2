## 运行中的完整连接

等待位 → 上游原生 RGB-D / Nero7 XY 卡尔曼测速 → 冻结单帧可见 OBB → 预测入区时刻 → 平滑接近 → 匹配工件速度 → 跟随闭合 → 宽度/受力持续确认 → 连续减速 → 静止端点 → 抬升 → RRT 载物搬运 → 配置料框投放 → 返回等待位。

1. 接近使用五次位置曲线，起点速度/加速度为零，接触点速度等于冻结工件速度、加速度为零。姿态仍使用旋转插值，时间进度改为五次函数。通常不再是严格的空间直线，这是使下降速度平滑转为带速所需的策略变化。
2. 优先尝试 2 s 接近，失败再尝试 3、4、5.5、6.5 s；每种时长分别尝试 OBB 方向候选。每次用 `p_contact=p_capture+v*(t_entry+T-t_capture)` 重新计算接触点，再做完整逆解与认证。不能把已过期轨迹延后播放，也不能只拉长旧轨迹却保留原拦截点。
3. 接触与 0.8 s 跟随必须在配置抓取区间内；接近、跟随及 1.5 s 减速全段必须在工作区内，并通过运动和几何检查。四个阶段构成同一条已定时关节曲线，由同一个发送线程连续采样。
4. 保留原闭合判断：水平 22 mm、竖直 12 mm、方向 0.25 rad；相对速度引起的 0.25 s 漂移仍须落在原位置容差内；剩余跟随时间至少容纳原 0.4 s 连续夹持反馈确认。保留 2 N 闭合请求、0.2 N 力门槛和原开口条件。未确认夹持就不能进入减速/抬升。
5. 闭合误差用同一反馈时刻的实际 TCP 和冻结视觉预测比较，不能把未来指令位置与旧反馈混算。100 ms 提前发送配置保留。夹持确认时，以该反馈的 TCP 和对应时刻的视觉预测建立载物估计；减速后只更新抬升的支撑起点，**不会再按传送带速度外推一次载物位置**。
6. 减速的预认证使用名义视觉附着；确认夹持后，实际发送边使用实际反馈建立的载物估计做碰撞检查。带面接触豁免仅在实测带面范围内，沿用原 5 mm 场景支撑带和 15 mm 高度条件；其他障碍仍拒绝。真机没有使用 MuJoCo 物体真值或接触真值。
7. 后续载物路线继续使用原 RRT-Connect。只合并严格共线的加密点，保留拐弯和反向点。按全曲线 q/v/a 极值统一缩放时间，再对最终发出的曲线做几何检查；保留 2% 定时余量并向控制周期取整。每段起止关节速度、加速度为零。
8. 下一段从上一段**指令终点**接入，同时检查实际反馈偏差不超过原 0.005 rad。后台规划期间独立发送线程持续保持该静止终点，且不与规划线程共享可变运动学模型；旧发送器停止并 `join` 后才能交给下一段。跨段保留实际发送历史，不能通过更换发送器清空速度/加速度检查。首个发送点也检查是否能从静止端点连续接入。

全部执行保留原任务/目标/版本、观测时钟代次、取消、反馈新鲜度、厂家接口及 CAN 发送所有权机制。不自动使能、开爪或校准零点。夹持力丢失、身份过期、反馈超时、发送间隔下超限等错误沿原停机路径退出。

## 参数与模块

现场配置 `src/nero_bringup/config/two_second.hardware.legacy_observed.yaml`：

```yaml
trajectory_profile: smooth
approach_duration_candidates_s: [2.0, 3.0, 4.0, 5.5, 6.5]
brake_duration_s: 1.5
candidate_planning_budget_s: 1.5
planning_budget_s: 8.0
command_advance_s: 0.1
pick_settings:
  full_plan_close_window_s: 0.8
```

每个候选的 IK 和几何阶段都有可取消预算；场景准备在通过 q/v/a 后进行，同一任务只准备一次，消耗总预算。实际提前发送截止与总预算取更早者，不保证每个现场目标都有足够时间遍历全部组合。超限和超时均记录阶段、时长及候选原因，不能强行执行。

现场仍继承原 `PickSettings` 在 100% 请求下的每轴 **2 rad/s、2 rad/s²** 软件包络；没有把它们改成无限大，也没有提高厂家固件上限。实际模型关节限位、TCP、等待位、料框和相机标定来源保持不变。旧配置若省略 `trajectory_profile` 仍解释为 `legacy`，便于历史回归；当前现场配置和模板均明确为 `smooth`。

| 责任 | 生产模块 | 与仿真关系 |
|---|---|---|
| 接近/跟随/减速参考 | `nero_core/two_second/smooth_reference.py` | 仿真兼容类直接继承同一实现 |
| 高精度数值逆解 | `precise_ik.py` | 同样采用 DLS + 缩放残差的 dogbox 回退；各用自己的私有数据 |
| 时长/候选/截止调度 | `smooth_planning.py` | 根据真实曝光年龄与测量速度重新预测 |
| 最终关节曲线、极值、时间缩放 | `trajectory.py` | MuJoCo 与真机共用五次样条和时间参数化实现 |
| 实测场景与载物检查、RRT | `planning.py` | 真机使用测量点云，不借用仿真物体真值 |
| 闭合、跟随、减速发送 | `streaming.py` | 原厂家位置命令接口，不假设硬件定时能力 |
| 静止交接/实际发送历史 | `stationary_hold.py`、`command_history.py` | 真机专用反馈与所有权检查 |
| 周期编排/投放/回位 | `execution.py` | 保留原宽度、力及关节反馈判断 |

逆解中的 1e-7 m / 1e-6 rad 是数值求解容差，用于减少相邻采样点的数值噪声，**不代表相机或机械臂具有该精度**。本入口继续使用可见 OBB 抓姿，不调用 GraspGen-X。

## 物理回归与边界

共享曲线和时间参数化在 MuJoCo 中完成两次单件回归：原仿真包络，以及每轴 **2 rad/s、2 rad/s²** 的当前真机软件包络。均为渲染 RGB-D → 原 Nero7 卡尔曼 → 单帧 OBB，带速 0.1 m/s；无抓取辅助、无焊接、无物体瞬移。后者：

- 物理夹持、抬升约 **196.4 mm**、稳定入框、返回完成；控制器限幅 **0 次**。
- 接近/跟随/减速关节曲线峰值加速度 **1.16087 rad/s²**；含搬运和返回的离散已施加指令加速度峰值约 **1.44970 rad/s²**。
- 搬运与返回的已认证曲线峰值分别约 **1.91694、1.92056 rad/s²**；经时间参数化，时长分别为 **3.74、4.02 s**。
- 环境构建 **0.7106 s**，首次物理步与传感器 **0.00193 s**；拦截规划 **1.3393 s**，其中 IK/q/v/a **1.1539 s**、几何 **0.1854 s**（子项不能再加到总项上）。抬升/搬运/返回规划各 **1.0174 / 0.8790 / 0.5792 s**。全流程仿真时间 **31.32 s**，运行墙钟 **23.99 s**，详细日志另耗 **0.05385 s**。

这些是仿真数据：仿真控制周期 20 ms，真机配置为 10 ms；仿真返回误差约 0.00753 rad，而真机仍要求 0.005 rad 并继续等待反馈到位。仿真执行器与接触冲量导致的实际关节加速度可高于指令包络；指令加速度和物理加速度不能混为一谈。载物碰撞在仿真中使用仿真刚体附着位置，真机改用测量估计。因此不能把该仿真当作真实设备发送频率、跟踪精度、夹持或投放的验收。
