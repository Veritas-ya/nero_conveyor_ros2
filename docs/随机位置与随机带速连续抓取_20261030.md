# 随机位置与随机带速的连续抓取（2026-10-30）

MuJoCo 两秒平滑入口新增逐件随机带速与横向位置范围选项。每件返回后才生成下一件；物件从上游 x=-1.28 m 出现。带速在每件开始时重新随机设置，在该件抓放期间保持；这不是单件运行中突然变速的验证。随机设定只作用于仿真环境，拦截输入继续来自渲染 RGB-D、Nero7 XY 卡尔曼测速和单帧可见 OBB。

## 运行

```bash
cd /home/ubuntu22/nero_conveyor_ros2
OPENBLAS_NUM_THREADS=1 MUJOCO_GL=egl PYTHONPATH=src/nero_core \
  python3 tools/run_two_second_grasp.py --profile smooth \
  --hardware-conditions src/nero_bringup/config/two_second.hardware.legacy_observed.yaml \
  --sim-gravity-compensation --sim-arm-integral-time-s 0.5 \
  --count 5 --seed 1543 --belt-speed-range 0.08 0.12 \
  --spawn-y-range -0.035 0.035 --bin-placement free_space \
  --seconds 300 --viewer --hold-viewer \
  --output runs/my_random_five.json
```

图形桌面必须有可用 DISPLAY/XAUTHORITY；无窗口验证时删去 `--viewer --hold-viewer`。本机桌面使用 DISPLAY=:1 和 XAUTHORITY=/run/user/1000/gdm/Xauthority。命令只启动仿真，不连接相机、CAN 或机械臂。显式重力补偿和受限积分伺服仍是未经过厂家辨识的仿真内环。

`--belt-speed-range` 单位为 m/s，每件独立抽样；省略时仍使用原 `--belt-speed` 固定值。`--spawn-y-range` 单位为世界系米，沿带宽方向，在原生生成器中抽样；省略时保留场景原配置。位置抽样继续沿用原生随机数顺序，避免显式覆盖 Y 时意外跳过抽样、连带改变姿态及材质序列。类别 ID 是生成的 T-LESS 模型 ID，不是视觉分类结果。随机种子可复现试验序列，不能由单一序列推断任意姿态都可成功。

## OBB 与轨迹各自负责什么

OBB 决定物体坐标中的抓取位置和方向。每件冻结一次抓姿与视觉速度，按曝光至接触时刻的时间差预测未来位置；随后转换成完整七轴、带 q/v/a 的抓取轨迹。交付后连续执行，后续帧不修改该件目标。之后日志中的抬升、载物转运和返回规划，分别负责这些阶段的运动路线，不重新生成 OBB 抓姿。

## 同框落点

`--bin-placement fixed` 保留旧固定落点。`free_space` 在实际夹持、抬升后，使用当前工件在投放姿态下的碰撞几何包围范围，以及同框已放物件的占用范围，选择不重叠、框内且间隙较大的落点。选择使用私有 MuJoCo 数据，不修改运行中的物体状态。新的 TCP 目标仍由原载物 RRT、时间参数化和碰撞检查生成路线；物理投放后仍验证框内、低于框沿、承重支撑、速度、脱离手指和连续稳定时间。

这部分明确使用仿真几何进行料框空间选择，未接入真实相机的料框占用感知，也未迁入真机。没有扩大料框、删除已放物件、重置物体或放宽入框检查。所有工件仍投放到同一指定料框。

## 保留的失败结果

最初显式覆盖随机 Y 的两轮都只完成一件，第2件出现接近阶段单侧接触，闭合后未确认夹持。尝试短轴优先排序没有解决，已经撤回。该工况仍未获得通用修复，不能把后续不同姿态序列的通过当作它的修复证明。

改用原生位置抽样后，固定落点一轮完成3件；第4件夹持、抬升、转运通过，但投放堆叠后的顶部 z=0.570390 m，高于框沿 z=0.520000 m 约50.4 mm，按原 `below_rim` 条件停止。随后只在该落点问题上引入同框空闲空间选择，保留相同带速、原生位置及姿态随机序列进行复测。

证据目录为 `runs/random_five_20261030_145952/`。`visible_random_five.json`、`short_axis_random_five.json`、`native_random_five.json` 分别保留前三轮失败；`preserved_failures.json` 记录前两轮诊断。最终结果以 `free_space_random_five.json`、其摘要及独立验证记录为准，不将多轮累计件数写成单轮连续成功。
