# 四个 OBB 抓姿并行规划的离线评估

当前程序从单帧物体点云产生 4 个 OBB 候选，按起始 TCP 与候选旋转之间的角度由小到大排列，同一运动时长内逐个尝试。它们不是网络评分；每个候选仍需要自己的逆解、时间参数化和几何检查。当前实机和仿真入口没有四候选并行规划。

## 测试方法

使用 `tools/benchmark_parallel_grasps.py` 对已有真机 RGB-D 记录离线回放，测试 271 和 301 两帧、0.0595 m/s 固定速度、当前配置等待位、2 s 接近时长、10 Hz IK 节点和 50 Hz 几何检查。两帧各两组，271 帧另有一组，共 5 对。机械臂状态采用配置的等待位及其模型正运动学，非当时记录的实际反馈；不连接相机、CAN，不发送任何命令。

串行基线使用原始生产规划器。线程原型在计算工件前预热 4 份模型及 4 条工作线程，使用相同冻结目标，每个线程有独立可变机器人模型和规划器，场景点云只读。4 个候选同时启动，但按原候选顺序等待和选择；较低优先级先完成不能覆盖尚未判定的高优先级候选。选中后通知其他任务取消，并记录全部线程退出时间。该原型只测试 2 s 时长，不实现生产规划器的多时长回退或实时任务切换。

| 指标 | 串行 | 四线程 |
|---|---:|---:|
| 冻结目标后至按优先级选中轨迹的中位数 | 0.523 s | 1.358 s |
| 范围 | 0.510–0.531 s | 1.301–1.388 s |
| 一次性模型和线程预热中位数 | 0.316 s | 1.092 s |
| 进程峰值内存中位数 | 约 719 MiB | 约 1065 MiB |

5 对均交付了相同的排序第 2 个候选（从 1 开始计数）。首个 271 帧对照中，同一条轨迹在 501 个时刻采样的七轴位置、速度和加速度逐值一致；这不是对其他工件或所有时钟条件的保证。四线程结果选出后线程退出在本次数据中约 0.4–0.6 ms；这不能证明其他输入下的可取消性或退出上界。

四线程比串行慢约 0.835 s，约 2.6 倍。各候选重复求解和准备各自的场景、线程资源争用都可能造成开销；本测试未作性能采样，不能将耗时归因于某一具体原因，也不能推断多进程一定更快。检测约 0.4 s、预热和读取保存帧均不计入上表的规划时间。

## 限制和结论

四种姿态在算法上可以同时计算，但该 CPU 线程原型在现有数据上没有加速，不应接入真机替代串行入口。进一步方案可评估更少的并发任务、常驻独立进程和共享不可变场景索引，必须分别测量启动、单件交付和资源占用；还需验证按时交付、优先级、任务取消、换目标、时钟重置和旧结果隔离，再考虑是否部署。

基准记录位于 `runs/parallel_grasp_benchmark_20261031/`。例如：

```bash
cd /home/ubuntu22/nero_conveyor_ros2
PYTHONPATH=src/nero_core:tools OPENBLAS_NUM_THREADS=1 \
  python3 tools/benchmark_parallel_grasps.py \
  --run runs/two_second_hardware/record_20261030_232939 \
  --config src/nero_bringup/config/two_second.hardware.legacy_observed.yaml \
  --frame 271 --speed 0.0595 --mode thread4 \
  --output runs/parallel_grasp_benchmark_20261031/example.json
```
