# 两秒轨迹的平滑对照与失败路径提速（2026-10-29）

后续进展：该平滑参考已接入独立 MuJoCo 入口，完成物理夹持、投放和返回，详见[MuJoCo 平滑抓取验证](MuJoCo平滑抓取验证_20261029.md)。后续已完成真机代码迁入及离线验证，见[平滑连接与时间参数化真机迁入](平滑连接与时间参数化真机迁入_20261029.md)。下文保存原运动学对照及其当时边界，不代表当前现场配置。

本轮读取19:28:59的保存记录，使用当前机器人模型、已确认TCP及已迁入的DLS/有界逆解做运动学对照。未连接相机、CAN或真实机械臂，未修改现场速度/加速度、两秒接近时间或闭合判定。

## 问题来源

现行 `Intercept` 在0～2秒采用位置直线插值、姿态Slerp；此前静止起步，2秒后改为工件速度继续跟随，七轴拟合曲线又要求末端速度为零。因此起步、转入跟随、跟随末端停车存在速度不连续或强制端点拟合。按100 Hz直接插值逐点逆解时，逆解允许误差也可能在相邻点之间形成微小台阶，二阶导数会放大这些变化。

提高逆解精度可以减少中段数值波动，但不能消除参考本身的速度突变。对于末端仍在下降而工件沿带面移动的情况，严格保持整段空间直线、到接触时又连续匹配工件速度，这些要求一般不能同时满足。有限加速度需要明确的起步、速度匹配和离开连接。

## 已接入真机入口的改动

1. `MeasuredPlanner.intercept` 先检查当前反馈、预测范围、逐点逆解和整条曲线q/v/a；有候选通过后才构建本次曝光的场景并做原几何认证。不再为已经违反运动约束的候选先支付场景过滤和索引构建成本。
2. 同一任务内的候选复用同一次场景准备；下一目标/下一次规划重新准备。未删除几何检查，也不跨曝光复用碰撞结论。公共场景错误仍直接停止，不反复按候选重试。
3. 限制错误现在包含实际上下限、超限轴号、轨迹时长和固定关节端点的仅加速度静止到静止时长下界。该下界是必要条件，不代表已经有可执行路径。
4. 采样点保留精确分段时间，并合并浮点表示造成的近重复时间点。诸如4.6与4.6000000000000005不能成为相隔机器精度的两个样条节点。

`deferred_scene_replay.json` 中，基于保存任务数据重建的生产规划器在约 **0.306秒** 内结束四个候选，均报告运动约束失败，场景准备请求数0。完整原始场景没有保存在这次任务目录，所以这只证明运动学失败路径的开销和调度，不能当作原始像素/点云逐字节复现或成功路径耗时。

## 独立的平滑诊断方案（未部署）

`experiments/two_second_grasp/smooth_reference.py` 实现单独命名的 `SmoothDiagnosticReference`：

- 五次位置曲线从静止起步，在接触点匹配冻结工件速度且加速度为零；姿态使用五次时间进度。
- 接触后保留0.6秒匀速跟随，再增加1.5秒平滑减速连接到静止。
- 该接近路径通常略有弯曲；它改变了原“严格直线匀速两秒”策略。减速段假设已确认夹持，真正部署前仍须加入相应运行时条件与载物碰撞认证。
- 仍使用原DLS及有界回退，数值求解容差在这个诊断工具内收紧到位置1e-8米、方向1e-7弧度；这些是模型求解精度，不是相机/机械臂实际精度。生产入口没有偷偷切换到该容差或参考。

同一保存任务、同一个排序后的第一候选，按当前每轴0.15 rad/s²与2 rad/s软件设置得到：

| 原参考的当前模型重建 | 2.0 s | 2.6 s | 82.7103 rad/s² | 未通过 |

原真机日志第一候选峰值是67.0469；上表82.7103是依据保存数据在当前模型重新生成的参考，不冒充精确复现原始运行。模型采样的TCP工作区、接触/跟随区间在上述诊断中也通过；没有完整场景点云，尚未做完整场景碰撞认证，也没有物理夹持、抬升、投放或发送时序验收。

结果支持两条后续路线：保留两秒接近时，用平滑速度过渡，并先核对真实硬件允许的加速度，再设置适用的软件约束；保留0.15软件上限时，允许结合未来工件位置选择更长的接近时间。5.5秒只是本次候选的离线结果，不是所有工件的固定新参数。预测时间延长也会放大冻结速度误差，仍需进一步验证。
