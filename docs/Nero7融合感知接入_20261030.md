# Nero7融合感知与持续测速

真机与相机预览统一使用原Nero7的 `rgb_depth → BlockTracker → KalmanMotion` 路径。检测、ID关联和卡尔曼源码保持原样；补入的 `base_plane.py`、离线验证模块也保留原文件哈希，来源与MIT许可证记录在vendor目录。新项目导入不依赖旧项目路径。

`perception_detection_mode` 默认 `rgb_depth`，支持原工程的 `rgb`、`depth_plane` 和旧基准 `legacy_depth`。`perception_plane_mode` 默认 `ransac3d`，也可显式选择 `fixed`。未使用给定带速替代视觉测量；已有显式固定带速选项仍按原方式标注来源。

启动时，已有原生深度绿色带面提取向原 `EmptyBeltCalibration` 提供15个不同设备时刻的实测支撑点集，沿用原配置的残差、倾角、空间支撑和跨帧一致性判据。使用侵蚀后的绿色带面点，不把工件或补洞点当成标定输入。校核失败会继续等待新观测，不回退为名义水平面或旧深度分割。相机标定、序列号、内外参或时钟代次改变后重新建立带面；完成一件工件后仅清理跟踪状态，保留同一标定上下文内的带面结果。

融合模式下，`maximum_target_height_m: 0.12` 表示基座坐标系的垂直高度上限。旧 `legacy_depth` 仍保持原配置的光轴深度差阈值，不再把现场12cm高度直接覆盖进去。传送带注册和ROI裁剪仍复用现有优化；裁剪射线、像素中心和内参保持原检测器的坐标语义。

本策略的测速区域为实测带面中位于抓取入口上游的部分，覆盖可见起点；机械臂抓取/搬运工作区保持独立。将该区域沿基座垂直方向扩展至配置的最大工件高度后投影到RGB，缓存此观测ROI，避免将夹爪下方和下游区域缺失深度的灰色背景送入上游目标检测。仅在算法输入副本上屏蔽ROI外像素，不修改原图、原生深度或内部有效深度门槛。进入ID关联前复用已有的实测工件几何检查；原始候选与剔除理由保存在诊断中，保留原检测位置。

测速线程只接收同一相机的观测、执行融合检测和更新原ID/卡尔曼。单帧目标点云、自体过滤和OBB计算交给独立单工作线程，最多一个在途任务，没有积压队列；该线程持有独立的机器人几何模型，并在启动时预热一次。机械臂反馈仅限制抓姿点云的自体过滤，不再阻止独立的视觉测速更新。

抓姿任务携带原曝光、设备时间、单调时刻、目标ID、跟踪代次、相机时钟代次、冻结速度和曝光对应的机械臂反馈。发布前再次检查观测年龄、任务代次和目标消费状态。取消、返回、切换任务、时钟重置后的旧结果不会发布。仍从原观测时刻计算位置预测，不通过更新时间来掩盖计算延迟。

沿用本策略已接受任务后冻结预测的行为。此时不再运行无用的目标处理，相机继续接收并监视时钟；画面中的滤波末值会按已有规则标注未更新。关闭及取消会等待当前几何工作退出，不遗留执行设备所有者。

诊断中，`grasp_geometry` 单独报告几何预热、目标检测和OBB耗时；`perception` 报告带面校核和测速阶段耗时。两条并行时间线不能相加作为单件总时长。

离线验证包括原合成RGB-D连续序列与原全图融合检测/跟踪逐帧对照、重复帧不能完成标定、时钟重置隔离、抓姿阻塞期间测速继续、旧目标/取消/返回的迟到结果隔离，以及原规划和执行回归。测试、构建和哈希记录在 `runs/nero7_fused_migration_20261030_side/`。

本轮433项算法/执行回归通过，最终入口与追溯的68项检查也通过（两组有重叠，不累加）。两个ROS包构建成功，安装版只读配置检查显示默认使用视觉卡尔曼，连接与命令数均为0。8张历史真实曝光的检测组件检查各得到一个通过现有几何检查的工件；该检查使用单帧实测带面，不代表生产15帧校核或现场速度精度验证。

本轮没有主动连接相机、CAN或机械臂。随后新增的88帧记录约为2Hz，不能重放原0.6秒窗口内至少8个独立观测的资格条件；没有用插帧补造缺失观测。不能据合成结果宣称现场约6cm/s的误差已经消除，仍需足够频率的连续观测确认。

构建后原启动入口保持不变：`ros2 run nero_core two_second_pick`，共享预览仍使用 `--preview`。运行中的旧Python进程需退出后重新启动才能加载新代码；关闭预览窗口不会停止抓取。
