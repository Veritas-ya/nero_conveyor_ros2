# GraspGen-X 候选分批和完整规划重试

2026-10-28，`tools/probe_measured_network_scene.py` 的无命令视觉诊断增加分批候选筛选。一次网络推理生成候选后，沿用原有评分顺序、几何、视觉、IK 和关节余量检查；每批沿用 12 个进入 IK 的预算。已经检查的候选及其夹爪对称形式不会重复进入下一批，预算跳过的候选保留用于后续批次。第一批无通过候选时也可继续，直到候选用尽、视觉失效或本轮仿真超时。各批筛选期间视觉继续更新，不重新加载或运行网络。

当一条完整规划以接近、闭合或抬升几何检查失败作为顶层原因时，可尝试下一候选：先关闭原完整规划器及场景监测，取消原视觉会话，再按原时间戳重放同一目标最近的观测，重新检验候选身份和观测年龄；新候选必须重新绑定原曝光场景并提交 `full_preplanned` 检查。每个上下文独立复制名义机器人模型和场景，避免复用或扩大已固定的起始关节容差。顶层交付截止、反馈、取消或场景类错误不会触发换候选；几何失败的内部候选搜索也可能包含截止时间拒绝，不能将所有内部拒绝归因于几何。此机制只存在于不发送动作的离线诊断，不能作为正在执行的机械臂换轨机制。

## 实测

真实 MuJoCo 渲染 RGB-D、Nero7 卡尔曼测速和官方 GraspGen-X 权重，无硬件连接、无仿真动作。一次网络实际目标推理生成 512 候选，耗时 0.505 秒；初筛 0.853 秒，和 2.318 秒场景准备并行，不应直接相加。网络模型加载 8.115 秒、单独预热 0.783 秒，均在单件运行前。

第一候选为编号 11，完整规划工作约 8.587 秒后因接近段几何/TCP 检查失败。第二批复用同一次网络输出，筛选耗时 0.706 秒，得到编号 53；新身份校验及独立完整规划上下文创建成功。第二候选的上下文一直处于等待，到仿真时限仍未提交完整规划请求，故未认证、未执行，原因尚需进一步定位。第二候选接纳时距原曝光已过去 9.28 仿真秒；不能把旧抓姿及旧场景直接称为当前碰撞安全。原场景监测与完整认证仍是执行前必要条件。

另一轮在首候选时发生 `full_pick_delivery_missed_start`，按时间失败停止，没有错误地转入候选重试。完整诊断记录分别见 [分批重试](evidence_retry_20261028/vision_retry.json) 和 [错过起始时间](evidence_retry_20261028/missed_start.json)。仿真 100 ms 参考提前量仅是待认证候选，未验证实际伺服延迟。

视觉、规划与抓姿流水线回归共 572 项通过；新增独立模型与会话测试后相关组合 16 项通过。ROS 2 Humble `nero_core`、`nero_interfaces`、`nero_bringup` 构建通过。GUI、物理夹持、投放与真实设备均未在本轮验证。
