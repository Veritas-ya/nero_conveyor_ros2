# 投放后直接返回当前等待位

现场 `two_second.hardware.legacy_observed.yaml` 和 `two_second.hardware.tracked_freeze.yaml` 将 `taught_return_strategy` 设为 `direct_to_wait`。抓住后仍按照现有逻辑预计算抬升、接入和示教投放；随后从示教投放终点规划一条连续的空爪路径到配置中的 `standby_joint_rad`，不回放旧返回示教，不途经旧示教终点。返回规划保持现有几何检查、速度和加速度时间参数化及 jerk 限制；张爪后使用当次释放估计重新检查该路径，才按现有发送链执行。历史返回文件未修改，它不作为当前返回段执行。

这条直接返回路径是当前场景下的规划结果，不是重新由人手录制的示教轨迹。预计算使用投放示教终点作为未来规划起点；执行时仍须满足原有实际反馈和路径交接条件。原先的 `recorded_then_wait` 策略仍可用于旧配置，配置默认保持旧行为。

## 离线验证

使用 `tools/replay_direct_return.py`，按当前现场配置在五份保存的带面场景和载物估计中从投放示教终点规划到当前等待位，五份均通过路径检查。单次轨迹时长 1.33 s；离线轨迹最大关节角速度为 J1 约 3.06 rad/s，最大角加速度为 J1 约 7.09 rad/s²。这些是规划曲线数值，不是实机反馈。报告位于 `runs/diagnostics/direct_return_20261114/saved_scene_replay.json`。

回放没有连接设备，场景和载物位置来自历史数据与估计，并非当前现场观测；也没有证明真机实际执行或投放成功。
