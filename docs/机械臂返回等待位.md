# 独立返回等待位脚本

脚本读取现场配置中的 `standby_joint_rad`，使用厂家 `move_j` 内部平滑关节运动返回等待位。默认只验证配置；只有 `--execute` 才连接 CAN、设置速度并发送一次关节目标。它不启动相机、不自动使能、不操作夹爪、不修改厂家速度/加速度限制，也不进行场景避障认证。

当前等待角度按 J1 至 J7 为 `[2.728, 43.334, -0.263, 98.814, 3.253, -4.163, 29.269]` 度，来源是用户提供的等待位，单位转换已写入现场 YAML。默认速度读取现场配置的 100%；`--speed-percent` 可覆盖本次运动的速度百分比。

## 在源码目录运行

只检查配置，不连接设备：

```bash
cd /home/ubuntu22/nero_conveyor_ros2
OPENBLAS_NUM_THREADS=1 python3 tools/move_to_wait.py --check-config
```

现场已恢复 `can0`、机械臂与夹爪已使能且反馈正常、空爪无受力、回位路径已确认后执行：

```bash
cd /home/ubuntu22/nero_conveyor_ros2
OPENBLAS_NUM_THREADS=1 python3 tools/move_to_wait.py --speed-percent 100 --execute
```

末次只读检查时系统没有 `can0`；脚本不会创建接口或自动使能设备。它沿用现有厂家适配器的反馈检查、发送所有权锁和电子停止接口。其他抓取程序仍占有发送权时，回位脚本会拒绝接管。

## ROS 2 安装入口

```bash
cd /home/ubuntu22/nero_conveyor_ros2
source /opt/ros/humble/setup.bash
colcon build --packages-select nero_core nero_bringup
source install/setup.bash
OPENBLAS_NUM_THREADS=1 ros2 run nero_core move_to_wait --speed-percent 100 --execute
```

可用 `--config /绝对路径/现场配置.yaml` 指定配置；省略时优先使用 ROS 安装配置，再尝试本仓库源码配置。脚本只要求关节顺序、等待关节、CAN、固件和运动设置，不要求相机/TCP/料框标定。源码入口可脱离 ROS 运行，但仍需项目的 Python 依赖和机器人模型。

## 执行与记录

发送前验证目标在当前模型关节范围内，并确认当前关节稳定；运行中使用原有反馈时钟映射，拒绝过期、倒退或重置的反馈。到位沿用最大关节误差 0.005 rad、连续新反馈稳定 0.1 秒的条件，默认超时 15 秒。夹爪受力达到现场原 `min_force_n`（当前 0.2 N）时拒绝移动，不会自行开爪或归零。

已经到位时不发送速度或关节目标；发送后取消、超时或反馈异常会尝试电子停止，随后释放连接与发送权。按 Ctrl+C 取消。厂家 `move_j` 自行规划内部曲线，因此该脚本不声称已对内部轨迹做主机 q/v/a 或碰撞认证；两秒抓取控制器的 `move_js` 高频发送与载物参数化逻辑仍由原入口负责。

每次执行创建新的 `runs/manual_return_wait/日期时间_唯一编号/`，保存 `events.jsonl` 和 `result.json`，包括配置 SHA-256、目标、速度、实际发送时刻、实际反馈、到位误差和失败原因。可用 `--output /新的日志目录` 指定位置，已有目录不会覆盖。

## 抓取程序中的自动回位

`two_second_pick --execute` 直接调用与本脚本共享的 `execute_return_wait`，复用已经建立的 CAN 连接、发送所有权和抓取程序取消事件；不会再启动子进程或建立第二个设备连接。启动读取正常反馈后，先检查夹爪已张开且无受力。若七轴与等待位的最大偏差大于原 0.005 rad，则使用厂家 `move_j` 按现场 `pick_settings.speed_percent`（当前 100%）回位，到位稳定 0.1 秒后恢复配置的抓取模式（当前 `js`），重新核对关节和夹爪，再开启相机和测速。

已经在等待位时不发送回位目标或速度命令。回位超时、取消、时钟或设备异常时停止，不进入相机/抓取流程；夹爪带载或未张开时直接拒绝，不自动操作夹爪。自动回位只用于启动恢复；任务已经接纳观测后的起点漂移仍拒绝执行，不使用旧目标跨越回位时间。正常每件结束后的认证返回路线保持原逻辑。

原抓取启动命令无需新增选项。默认或 `--check-config` 仅输出 `startup_return_wait_policy`，不连接设备；必须有 `--execute` 才能触发设备路径。`summary.json` 中的 `startup_return_wait` 和 `events.jsonl` 中的 `startup_return_wait_*` 保存跳过/发送/反馈/到位/失败证据；回位耗时包含在设备启动阶段内，不与设备启动耗时相加。
