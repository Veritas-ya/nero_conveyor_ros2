# 连续抓取：相机冻结与回位解耦

连续抓取和多件抓取的 smooth/synchronized 策略默认启用下一件预取。匹配版、固定位置单帧版和粗算优先版共用同一交接机制。单次抓取、只开相机、旧轨迹策略保持原调用方式。

## 当前时序

1. 当前工件被接纳后，原执行器独占机械臂，继续接近、闭爪、减速、示教投放和返回。视觉线程可以独立冻结下一件的点云、原曝光时间、原速度和真实反馈依据。
2. 下一件最多缓存一份，不累计无界队列。原生深度单帧模式还按已知速度预测最近已接纳工件的位置，抑制同一工件在相邻曝光中被再次接纳；匹配模式保留真实观测与原ID资格检查。
3. 下一件点云一旦及时冻结，独立规划器立即计算完整路径：尚未确认回位时从配置等待位模型路点推测；已经确认回位时，从主循环提供的最新实际反馈规划。不等待本轮回位路径交付才开始推测计算。初次尚无回位预测时先计算最早可行预约，明确这是推测路径，不能取得执行权限。最后一段空载回位路径交付后，再用该段的绝对起点、时长和默认0.2秒估计余量更新可用时刻；原预约早于该预测时重新计算接触点与完整路径。相机和视觉几何继续使用各自的私有模型，任何预取任务都不能修改当前示教回程的目标、版本、场景或发送器。
4. 返回途中的预规划起点是配置等待位模型路点，明确标为规划假设。回位确认后的规划起点为实际关节、法兰和夹爪反馈，保留原CAN包时间戳及时间对齐依据，不使用工件曝光时的旧机械臂状态，也不伪造设备反馈。碰撞、逆解、关节速度/加速度、完整路径和绝对发送截止仍使用原规划检查；延后最早发送时刻会重新计算接触位置和全路径，不平移旧轨迹。
5. 当前执行器根据真实反馈确认回到等待位，且夹爪张开、无载后，才能交接下一件。执行前重新核对真实反馈、FK、目标/曝光身份、相机时钟代次、路径版本、场景版本和实际发送截止。主循环持续提供实际反馈；实际等待位与预规划起点偏差超过0.005 rad或夹爪开口变化超过0.002m时，后台保留同一工件曝光并从实际状态重新规划。执行器在最终接管时仍保留原0.005rad起点门槛，不直接发送起点不匹配的缓存曲线。
6. 回位、恢复或上轮存档使旧预约过期时，清除旧模型路径，保留已经及时接纳的原始点云、曝光和带速。每次回位时间更新或真实回位确认都会允许一次重新求解，禁止平移旧曲线。初次推测规划失败时先记录完整失败细节并保留曝光，等时间依据更新后再试，避免在同一预测下反复消耗CPU。目标已越过抓取区，或真实回位后重算仍不能满足约束时才跳过，释放缓存寻找后续目标。

启动时的首次自动回位仍在打开相机之前完成。这项功能不允许两次抓取同时执行，也不改示教轨迹、等待位、速度/加速度上限、发送提前量、标定或带向。

## 曝光与机械臂状态

预取时复用同一个相机。自体点云过滤使用实际CAN关节历史，在曝光映射到主机的时刻做有前后真实数据包的插值，禁止外推；缺少任一轴的历史括号、括号跨度超过50ms或原反馈检查未通过时，该帧不能接纳。夹爪宽度来自原新鲜反馈，并非从未来等待位推断。

这是CAN接收时间边界上的对齐，仍不等于编码器内部采样与相机曝光的硬件同步。原始点云和时间戳不改写。

`maximum_observation_age_s` 仍用于新曝光及初次预取接纳。已经及时接纳并冻结的观测，在回位后依据原时间戳、固定预测和完整认证路径的绝对发送截止使用，不重新标成“新曝光”。这一点与原程序冻结后等待未来发送时刻的语义一致。

## 配置与记录

现有连续抓取命令不需要新增参数。配置解析默认：

```yaml
continuous_lookahead_enabled: true
lookahead_return_margin_s: 0.2
```

可显式设 `continuous_lookahead_enabled: false` 恢复原逐件回位后重新取帧的顺序。`lookahead_return_margin_s` 最少0.1秒，仅是规划可用时间的估计余量，不替代真实回位确认，也不保证规划能在该余量内算完。

原事件日志增加 `lookahead_planning_started`、`lookahead_planning_deferred`、`lookahead_frozen`、`lookahead_return_window`、`lookahead_plan_ready`、`lookahead_rejected`、`lookahead_plan_expired_replan`；执行事件增加 `lookahead_plan_adopted`、`lookahead_start_replan`。拒绝记录保留 `failure_details`、是否已经生成模型路径及截止余量，可区分规划失败和路径生成后错过发送。模型路径不代表真机成功。

终端显示 `[预取规划]`、`[预取]`、`[预取待重算]`、`[预取重算]` 和 `[预取跳过]`。预览可展示下一件原曝光和模型路径，正在执行的动作仍以原执行阶段和真实反馈记录为准。

## 验证边界

自动化验证使用假设备、合成时钟和离线模型，覆盖回程中冻结、提前规划、真实回位前禁止交接、预约过期后保留原曝光并重算、越过抓取区后释放、时钟/身份/版本作废、线程退出和预规划路径复用；这些验证没有连接相机/CAN或发送机器人/夹爪命令。实际CPU竞争、上游深度可见性和实物成功率仍需现场运行记录评估。

## 2026-11-13 发送卡顿修正

15 cm/s 实机记录中，原定10 ms的发送间隔在示教投放、回位时出现100～319 ms长间隔；几何检查超过当前认证时窗后触发重试、取消和恢复。SDK调用本身大多小于1 ms，不能把这些上位机准备空档当成设备等效延迟。

运行检查保留原来的三个时间切片、0.008 rad关节弦采样间隔和发送时窗。仅合并同一周期内完全相同的状态/时间，几何采样只计算位置；机器人和载物的KD树球查询按原半径批量计算，并保留原候选顺序和精确凸包窄相检查。对明确只含带面观测的场景，载物KD树包围盒若能严格证明所有载物点与带面保护带分离，则省去不可能命中的完整点云转换与查询；边界附近仍执行原精确检查。

每段发送结束后记录 `dispatch_timing`，包含实际发送间隔、准备耗时、反馈读取和预约迟到的中位数、95分位与最大值。原碰撞阈值、速度/加速度限制、示教时长、90 ms提前量、标定和等待位不变。这些优化降低重复计算，不承诺普通Python进程在所有现场负载下都能保持严格100 Hz，仍须用下一轮实机日志验证卡顿是否消失。

## 2026-11-13 提前规划门控修正

22:42:27这轮日志中，下一件在运行后77.082秒完成冻结，却等到80.630秒才得到本轮最后回位路径的时间预测，后台在此前约3.55秒没有开始求解；81.081秒才生成路径，实际回位段82.557秒完成。因此旧版并非所有情况下都等到真实回位后才求解，但仍存在“等待最后回位路径交付”的计算门控，不能称为冻结即开始规划。该门控现已移除。

`poll_ready()`和`claim()`继续代表执行接管资格，真实回位前返回空或拒绝；模型计算完成由`lookahead_plan_ready`独立记录，包含`return_confirmed`、`return_prediction_known`及`schedule_revision`。诊断里的`target_processing_paused`也按实际预取开关计算，不再把所有本轮执行期间都标成视觉暂停。

本修正实现的是下一件规划启动不依赖回位信号；没有把100Hz发送线程中的运行碰撞扫掠迁移到另一执行单元，不能据此声称“计算与发送已经完整隔离”或实机卡顿已经消除。

## 2026-11-14 运行扫掠与发送分离

真机匹配/单帧配置现改为独立进程20 Hz运行碰撞监测，发送端100 Hz按已有完整连续曲线插值。后台计算未完成时继续使用原曲线，超过监测反馈200 ms有效期或检查失败后取消并沿用原恢复逻辑；运行监测不再覆盖每个发送周期的中间实测状态。非阻塞反馈读保留原包时戳，且取消、版本、新鲜度、FK、夹持及发送速度检查继续生效。具体设置和验证边界见[运行碰撞监测与插值发送](运行碰撞监测与插值发送.md)。这一步迁移了运行扫掠，尚不等于已证明现场所有调度/SDK卡顿消失。


## 2026-11-14 回位后使用实际反馈起点

11:45这轮日志的第3～10次尝试中，第7关节相对配置等待位偏差约0.386～0.393°。原回位完成判据允许1°，预取轨迹复用门槛为0.005rad（约0.286°），且后台一直从配置等待位求解，导致已算出的轨迹在交接时反复被弃用。

现在 `confirm_return(state)` 接收回位完成后的实际快照；等待下一件时主循环通过非阻塞反馈读取持续更新邮箱。后台线程仍不拥有设备对象或发送接口。快照深复制，保留包时间戳；关节/法兰/夹爪反馈须在原200ms时效内、时间不倒退且时钟代次一致，并通过原1°等待位、张爪和无载检查。反馈暂不可用时等待新快照，不采用配置角度代替实际反馈。主循环未读到新快照不会刷新旧快照时间。

规划提交事件与完成事件中的 `start_state_source` 区分 `measured_confirmed_wait_feedback` 和 `configured_wait_model_waypoint`，另保存 `planned_start_joints_rad`、`start_feedback_stamps`。实际状态与已有/正在计算的起点变化超限时记录 `lookahead_wait_state_replan`，使旧求解失效并保留原目标重算。执行前仍检查最新反馈、原发送截止、目标/曝光/版本/场景及起点偏差；不平移旧轨迹，不放宽关节或碰撞限制。

此修改不涉及返回阶段的实际发送间隔超限，也不保证所有实际起点均有可行轨迹。验证包括0.00685rad残余偏差、回位中推测路径转实际起点重算、快照复制、过期/未来/缺失反馈、时钟倒退、夹爪带载/未张开、超出等待区、规划期间起点变化和原交接/恢复路径；测试均未连接硬件。
