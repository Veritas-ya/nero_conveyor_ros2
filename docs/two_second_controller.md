# 独立两秒直线抓取控制器（MuJoCo 实验）

该入口与 `full_preplanned` 独立，不调用或修改该控制器，也不连接硬件。仿真重置时把机械臂放到配置的等待位，不表示已验证从其他姿态到等待位的路径。带速默认设定为 0.10 m/s，可通过 `--belt-speed` 调整（单位 m/s）；控制器仍使用视觉测速，抓取工作区维持原配置，相机使用扩大后的仿真视野。

视觉在抓取区上游持续测速，默认在入口上游 0.35 米以内、有效测速观测跨度至少 0.45 秒且规划时间充足时，取该帧 RGB-D 目标点云构建可见 OBB（未调用抓姿网络），冻结该帧 OBB 和速度并立即开始规划。以曝光时刻预测物体抵达抓取区入口的时间，作为轨迹开始时间；这是冻结速度下的预测，不是实际入区的传感器确认。以曝光时刻 `t_obs` 为基准计算：`p_contact = p_obb(t_obs) + v * (t_start + 2 - t_obs)`。到预测入区时间后开始，TCP 从等待位置沿直线运动 2 秒，方向在起点和 OBB 抓姿之间插值；闭合命令在计划终点排队，闭合期间按冻结速度跟随 0.6 秒。保留之前提出的 100 ms 仿真参考提前量，实际执行和发送应用存在仿真延迟，应看记录的实际 TCP 反馈。

独立线程按多个 OBB 等价方向采样求解 IK，检查关节位置、速度及采样的 MuJoCo 静态几何碰撞；规划未及时交付、逆解不收敛、碰撞或者预期接触点超出工作区时不发送过期路径。检查没有覆盖加速度、真实设备、移动场景连续碰撞或完整闭环，不能当作 `full_preplanned` 的完整认证或实机控制器。闭合后同时检查仿真夹爪阻塞反馈和双侧物理接触，再规划抬升；利用仿真物体高度及接触检查是否真正抬起，之后才规划向指定料框移动和张开放料。搬运时失去夹持反馈会停止。放料后使用物体碰撞几何、料框支撑接触、速度及无手指接触进行独立验证。控制器使用仿真接触和物体抬升高度作为条件；视觉截取与测速不使用真值。转运后检查料框内放置，再规划返回等待关节位，返回成功后生成下一件。

在项目目录运行：

```bash
PYTHONPATH=src/nero_core:src/nero_bringup MUJOCO_GL=egl OPENBLAS_NUM_THREADS=1 \
  /path/to/python tools/run_two_second_grasp.py \
  --output runs/two_second_controller/run.json --viewer --hold-viewer
```

`--start-reserve-s` 是上游观测到预测入区之间最短规划预留时间，默认 1.5 秒；入口时间根据观测及速度计算，2 秒是执行直线所需的时间。`--vision-max-speed` 默认为 0.30 m/s，是视觉滤波器有效速度上限，不提供速度测量值。输出 JSON 包含每个候选的失败原因、速度、计划时刻、预测接触点、TCP 实际反馈和手指接触力。

例如以 15 cm/s 运行，可增加 `--belt-speed .15 --start-reserve-s .8`。预留时间必须容纳实际规划耗时，交付晚于预定开始时不会执行。当前只检查预测接触点位于抓取区；闭合跟随段可能越过区间末端，尚未完成对该段的工作区约束。

## 连续投放与限制

使用 `--count 5 --seed 1543 --belt-speed .20 --start-reserve-s .8 --bin-id 1` 请求五次。随机种子从当前仿真启用的五类 T-LESS 工件中不重复抽取；一次只生成一件，完成返回后才生成下一件。`--min-track-age-s .9` 可要求同一视觉轨迹累计观测至少 0.9 秒后再冻结速度；这不改变卡尔曼测速合格性检查所用的 0.6 秒近期观测窗口，可能降低测速误差，也可能错过规划时间，应结合现场视野和带速验证。

闭合动作是 -1（+1 为张开，0 仅半闭合）。载物转运采用关节空间 RRT-Connect，搜索多个逆解与末端朝向，允许路径绕行；路径分段根据关节速度与加速度限制生成时间，按关节空间间隔采样检查机器人、载物与场景的碰撞。抬升阶段也以仿真物体随 TCP 刚性附着的假设采样碰撞，允许开始时已有的带面支撑接触。返回轨迹检查机器人与场景和已放置工件的碰撞。放置后需要碰撞几何位于料框内、接触料框、与手指分离并稳定 0.5 秒；五件完成后再检查料框内各件状态。料框由 `--bin-id` 明确指定，不伪造类别识别。

载物几何和附着变换直接读取 MuJoCo 真值，仅用于物理仿真实验；碰撞是离散采样且将场景视为静态，不能代表连续碰撞认证或真实抓取场景。两秒接近阶段尚无完整加速度认证，夹持、滑移、落料和跟踪也未覆盖现场不确定性，因此不能用于真机。速度冻结后不使用后续视觉更新，预测误差会随时间累积；增加观测时长不保证所有工件成功。

## 仿真与真机的触发逻辑

两入口现在共同调用 `nero_core.two_second.reference.predict_entry_time`，包括入口上游最多0.35 m的冻结窗口、从原曝光起算的入区时间和规划预留。仿真沿世界X取标量，真机沿配置带向投影。共享的是观测接纳和两秒预测算法；实际几何、机械臂反馈、关节速度和碰撞验证仍由各自适配层处理。真机全闭合跟随段必须留在区间内，仿真实验入口仍只检查接触点；不能将仿真通过视作真机检查通过。
