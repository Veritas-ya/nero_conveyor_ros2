# 真机与仿真自检（2026-10-30）

后续配置已按用户提供的厂家加速度数据改为8 rad/s²，本报告的2/2和三件成功保留为历史验证。新上限的单件回归在载物搬运时夹持开口异常停止，不能套用本报告的成功结论；见[后续修正及验证](规划交付与厂家加速度修正_20261030.md)。

本轮修复后，按对齐的软件条件完成连续三件 T-LESS 的物理夹持、同框投放和返回。**真机与仿真仍不是同一个经过标定的物理系统**：成功测试使用了显式的仿真伺服模型，真实相机、安装位置、料框、厂家内环及 CAN 延迟没有在本轮实测。本轮真实设备连接数、真实发送命令数均为 0。

## 已修正的确定性问题

| 问题 | 失败机制 | 修正及验证 |
|---|---|---|
| 平滑配置覆盖默认料框名 | 参数循环把 `common_bin` 覆盖成 `1.5`；夹持后构造后续任务时会触发 `KeyError` | 使用独立 `default_bin` 变量；直接读取现场 YAML 的回归及安装入口检查覆盖该问题 |
| 闭合时钟不一致 | 真机用提前100 ms的轨迹采样时刻判断已接触，仿真使用实际反馈时刻 | 共用 `feedback_gates.closure_feedback`：以实际反馈时间判断接触，按未来发送时间核对剩余跟随时间；运动指令提前100 ms保留 |
| 到位只看单帧关节偏差 | 未来指令已经到终点时，实际运动可能还未结束；阶段过早交接 | 等待实际反馈时间到达轨迹终点，并使用原0.005 rad与原0.1 s稳定到位条件；重复反馈不积累确认时间 |
| 刹车边界先检查、后处理反馈 | 恰在该帧完成0.4 s确认时仍可能被判为未夹持 | 先处理本帧夹持反馈，再检查是否允许进入减速 |
| 不等发送间隔下的加速度计算 | 差分速度的时间位置在各区间中点；只除最新区间会高估加速度 | 改用相邻区间中点间距；真实1.9 rad/s²、不等时间间隔的用例不再被误报为4.75；真实超限仍拒绝 |
| 不同步的CAN反馈直接做FK比较 | 关节和法兰反馈分别更新；较新关节与较旧法兰对比，运动中可能越过5 mm/1°门槛 | 各关节按自身反馈包时间记录历史，只在实测区间内插值到法兰反馈时间；原始最新关节继续用于控制和碰撞；原容差保留，真实6 mm偏差仍拒绝 |
| 几何计算后发送旧采样点 | 几何检查耗时波动使预计发送与实际发送时刻不一致，离散指令会出现额外加速度 | 对下一个发送周期的曲线及反馈连接进行采样检查，在该时间窗内按实际发送时刻重新采样；超出检查时窗直接拒绝；保留实际发送后的q/v/a检查、身份检查和取消检查 |
| 仿真关节余量比真机更大 | 仿真0.055 rad、真机0.020 rad，实际逆解满足真机边界却被仿真拒绝 | 对齐模式直接继承真机运动学模型的边界及余量，保留物理关节限位 |
| 仿真搬运逆解使用另一套回退 | 部分料框位的普通DLS失败，而已部署的有界回退能够求解 | 对齐模式的接近和搬运复用生产 `PrecisePoseSolver`，按配置投放TCP的完整位姿规划 |
| 同框叠放被误报为无支撑 | 第二件放在第一件上，没有直接接触箱底 | 只读物理承重接触图，允许通过框内、稳定且脱离手指的其他工件连接到料框；浮空接触环和无承重接触仍拒绝 |

发送时刻回归使用理想反馈设备和可控的1/5 ms计算延迟，复现了原连续曲线合格、晚发后离散指令达到2.118 rad/s²的情况。它验证了发送逻辑修复，没有实测CAN性能。超出已检查时间窗的25 ms延迟用例仍拒绝发送，取消发生在最终采样期间也不会发出该点。

CAN时间对齐使用适配层已记录的反馈包接收时间及其单调时间映射，不能当作设备硬件同步。无实测插值区间时不外推；时钟代次变化清理历史。夹持载物估计也改用最新关节FK对应的关节时间，避免用旧法兰时刻预测的工件位置去减当前关节FK位置。合成20 ms反馈错位回归和原SDK快照测试通过，仍待真实运动数据核对。

默认料框错误是上一轮迁入代码的缺陷。本次没有运行真机，不能把它说成某次历史真机失败的已证实原因。

投放位排查中曾考虑高度原因；最终关节余量对照证明其直接拒绝原因是0.055/0.020的不一致。最终代码沿用现场投放位及仿真原投放位，撤销了中间尝试的仿真高度调整。

## 成功物理测试的条件

仿真默认位置PD执行器的稳态误差可超过0.005 rad。只增加重力前馈的严格测试仍在跟随结束处以约 **0.00704 rad** 误差超时，记录为失败。

成功测试显式启用了 `--sim-gravity-compensation --sim-arm-integral-time-s .5`。它在原MuJoCo位置PD上增加受模型扭矩范围限制的积分补偿，保留质量、惯性、摩擦和接触动力学。没有修改关节状态、物体状态或轨迹参考；没有焊接或抓取辅助。**这套参数没有经过厂家内环辨识，不作为真机算法或真机内环参数下发。**

| 工件生成类别ID | 视觉冻结X速度 m/s | 物体实际抬升 m | 返回最大关节误差 rad | 结果 |
|---|---:|---:|---:|---|
| 12 | 0.099046 | 0.057334 | 0.003976 | 夹持、同框投放、返回通过 |
| 6 | 0.099679 | 0.055687 | 0.003715 | 夹持、同框叠放、返回通过 |
| 9 | 0.100193 | 0.055603 | 0.003701 | 夹持、同框投放、返回通过 |

设定带速为0.1 m/s。类别ID仅标识仿真随机生成的模型，不是视觉分类输出；三件均按明确配置放入同一料框。

三件最终均在框内、低于框沿、脱离手指且稳定；第二件的实际承重链为“第二件→第一件→料框”。承重接触使用MuJoCo求解的正法向力；柔性接触裕量内的亚毫米几何间隙不被误判为没有支撑。每帧重新计算世界坐标和接触，缓存仅保存不可变的局部碰撞网格。旧分类任务的状态标签作为原始诊断保留，同框策略由独立物理验证确定成败。

控制器限幅0次，已施加离散指令加速度峰值约 **1.46023 rad/s²**。实际物理关节加速度还包含执行器响应与接触冲量，不能当作指令限值；本报告不声称物理加速度始终小于2。

三次拦截规划墙钟约 **1.077、1.098、1.211 s**。末次的IK/q/v/a为0.840 s，几何0.372 s，这些是1.211 s的组成部分。全程仿真时间 **106.13 s**，运行墙钟 **110.07 s**，最后详细日志保存另耗 **0.381 s**；墙钟与仿真时钟不同，不能相加。启动到环境就绪约0.939 s，包括配置及运动学模型准备。后续抬升/搬运/返回规划分别在报告的逐件`attempts`中保存。

## 仍然不同，可能造成实机失败的条件

- **几何和坐标系**：真实等待TCP约为基座系 `[-0.4030,-0.0328,-0.0166]` m；仿真采用传送带上方的等待姿态。真实传送带方向接近基座-Y，仿真沿世界X。现场投放TCP、相机外参及实际料框与合成现场分别配置。相同的软件限值不意味着相同的逆解分支、避障难度或视野。
- **厂家执行器**：仿真内环模型与厂家位置控制、CAN周期、摩擦补偿、负载响应及夹爪受力标定还未对照。原PD严格测试失败正说明该差异不能忽略。真实反馈达不到条件时仍停止。
- **碰撞输入**：真机使用冻结曝光的可见点云和实际TCP建立载物估计；仿真载物碰撞使用完整物理网格附着位置。不可见形状与未被相机覆盖的场景仍需实际验证。
- **成功判定**：真机入口目前确认关节、夹爪宽度和力反馈，报告仍保留`physical_grasp_success=null`及`physical_bin_placement_verified=false`。仿真的实际抬升和框内稳定由独立物理验证确定；实机还需要独立的工件抬升/落料观测。
- **时钟和计算负载**：真机采样使用主机单调时钟与实际CAN发送时间；仿真用物理时钟。仿真某些物理验证步骤会消耗墙钟而不推进物理时间，因此结果不是100 Hz真机实时性验收。实际发送超出已检查时窗、反馈过期或时钟重置均拒绝。
- **速度与窗口**：0.3 m/s是测速器可接受范围，不是抓取成功速度保证。固定2 s接近和0.8 s跟随时，0.48 m区间在忽略OBB中心偏移的条件下仅容纳约0.171 m/s；更快工件可能没有当前候选时长的可行解。检测、规划和厂家参数准备还会消耗上游预留，不能使用过期轨迹凑一次执行。

保存真机任务复算仍没有原始场景，不能证明该帧的完整碰撞认证。本轮已验证配置料框的纯运动学逆解可达，以及稀疏IK后最终曲线的加密FK；`scene_certified`保持false。现场实际等待位、张爪零点、设备状态也没有在本轮读取。
