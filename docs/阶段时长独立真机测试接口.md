# 阶段时长独立真机测试接口

入口：`tools/phase_timing_test.py`。使用当前工作区源码，无需重新安装 ROS 包。

本入口固定闭爪后跟随时间，在线搜索接近和减速时间，并沿用原有完整规划、关节限值、工作区、碰撞检查、发送时限、反馈检查及示教投放/返回。算法仍是离散候选搜索，不是连续优化或全局最优求解。

默认接近固定 **1.1 s**、跟随固定 **0.1 s**，只搜索减速候选 **0.4 / 0.6 / 0.9 / 1.2 s**。如显式提供多个 `--join-times`，才恢复接近时长搜索。每次运行将现场配置复制到新的测试目录；不写回原 YAML，不改变等待位置、抓取范围或关节限值。接近1.1秒仍须通过轨迹和空间检查，不代表所有目标都可行。

## 1. 先检查入口

在工程目录运行，带速单位为 **cm/s**：

```bash
cd /home/ubuntu22/nero_conveyor_ros2
OPENBLAS_NUM_THREADS=1 python3 tools/phase_timing_test.py --belt-speed-cm-s 50.8 --check-config
```

省略 `--execute` 只检查配置，不连接相机/CAN，不生成在线抓取轨迹，也不发送运动指令。检查成功应输出 `configuration_valid`、`hardware_connections: 0`。

## 2. 真机单次测试

沿用原有机械臂上电/使能及传送带准备流程。关闭占用同一相机/CAN的原抓取进程，再运行新入口。把示例带速换成现场实际值；入口不负责设置传送带速度。

```bash
cd /home/ubuntu22/nero_conveyor_ros2
OPENBLAS_NUM_THREADS=1 python3 tools/phase_timing_test.py --belt-speed-cm-s 50.8 --follow-s 0.1 --count 1 --record-rgbd --execute
```

`--count 1` 沿用原入口的反馈周期计数，不表示保证成功一件。终端会显示本次选择的接近、跟随、减速时长；无可行组合时记录拒绝，不放宽限值。此入口沿用 `scheduled_attempt`：按计划闭爪、减速，夹持反馈确认可跨越减速阶段；它不是“反馈确认夹稳后才减速”的闭环切换。

多周期可改为 `--count 5`；连续运行使用 `--continuous`，不能与 `--count` 同时提供。`Ctrl+C` 沿用原入口的退出处理。

## 3. 调整搜索范围

例如只比较 0.4 和 0.6 秒减速：

```bash
OPENBLAS_NUM_THREADS=1 python3 tools/phase_timing_test.py --belt-speed-cm-s 50.8 --follow-s 0.1 --join-times 1.1 --brake-times 0.4 0.6 --execute
```

候选必须为正有限数且严格递增。跟随固定为一个正值；当前独立入口不支持 0 s，可通过原抓取入口保留 0 s 基线。调整候选不改变关节限值。

其他参数：

| 参数 | 含义 |
|---|---|
| `--config PATH` | 原始现场配置，默认 legacy_observed.yaml |
| `--max-target-length-cm 20` | 独立入口默认长边识别上限20cm，触发与完整识别共用；原入口未配置时保持16cm。最大可配置30cm，不代表夹爪/工作区能抓这么大的工件 |
| `--output PATH` | 独立输出目录，必须不存在；默认 runs/phase_timing_test/时间戳 |
| `--timing-history-run PATH` | 指定已有独立实验目录作为首轮测时来源；默认在本工程最近32个独立实验目录中选最近有有效测时且配置匹配的一次 |
| `--full-frame-geometry` | 在本次私有配置关闭局部工件识别，保留原完整帧处理，用于对照；默认启用局部处理 |
| `--mode robust` | 默认加入 15 ms 时序与 3 mm 位置设计余量；尚非实测不确定性边界 |
| `--mode nominal` | 不加上述时序/位置余量；仍有原关节/几何检查 |
| `--stop-interval MIN MAX` | 沿传送带方向投影的停止区间，单位 m；默认取原抓取区间，完整工作区检查也保留 |
| `--preview` | 使用原入口的共享相机预览 |
| `--record-rgbd` | 保存同源 RGB-D，增加磁盘占用 |
| `--freeze-source tracked` | 使用原跟踪冻结来源；应配对应 tracked_freeze.yaml |

## 4. 离线回放同一接口

不需要相机/CAN，也不接受速度覆盖，使用记录里的目标速度：

```bash
OPENBLAS_NUM_THREADS=1 python3 tools/phase_timing_test.py --replay-run runs/control_panel/pick_20261113_110415_884109 --follow-s 0.1
```

回放复用完整规划器，返回 `plan_ready` 或 `planning_rejected`，保留原因和候选诊断。只重建日志最后一次冻结输入，假设张爪状态并由模型重建法兰；规划通过不等于真实抓取成功。

## 5. 日志与 Python 接口

每次运行目录包含：

- `effective.yaml`：本次独立配置。
- `experiment.json`：源配置/代码哈希、候选、算法与未标定假设。
- `invocation.json`：调用参数和是否明确要求执行。
- `hardware/`：真机原生日志，包含 `planning_delivery` 的 `trajectory_diagnostics.phase_timing`、候选搜索、完整关节速度/加速度峰值、闭爪时刻及夹持反馈。被跳过的目标也应保留统计。
- `replay.json`：仅回放时生成，包含所选时长与完整规划结果。

Python 调用方可导入 `nero_core.two_second.phase_timing_test.prepare_test` 创建独立配置，再使用 `CellConfig.load` 和 `plan_once(config, target, state, clock=...)`。`target` 使用已有 `MeasuredTarget`，`state` 使用已有反馈快照，时间戳必须处于传入时钟的同一时间轴。`plan_once` 返回已有认证规划对象，仅规划，不连接硬件或发送命令。真机执行使用上述 CLI 复用原执行器。

## 实验含义

0.1 s 是操作者指定的试验时长，不是测得的闭合上界；200 ms 软件夹持确认不再全部计入匀速跟随时间。配置明确标记 `experimental_hardware`，不会伪装为 `measured`。旧的 `assumed_offline` 参数仍不能直接执行，新实验配置从原抓取入口直接执行也会在连接设备前被拒绝。

本入口使用原软件配置的关节限值；发送指令差分加速度检查是否启用仍沿用现场配置。它不证明固件保护、实测关节加速度或夹持防滑能力。现场测试应记录从闭爪命令到有效夹持的时间、减速期间的跟踪误差/滑移、完整成功与跳过次数。

## 长工件与尺寸稳定性（2026-11-13）

第一件保存帧在冻结窗口内估计长边16.8cm，被旧16cm硬门槛排除。独立入口改用20cm适用范围，避免已观察到的13.8–16.8cm波动反复跨越16cm阈值。原等待位置、冻结窗口、夹爪开口、抓姿与完整点云碰撞检查保持原设置。触发搜索画面随配置长边增加适当扩展，保证不会靠裁短点云通过尺寸检查。

长度估计仍使用同一曝光的PCA与1%/99%分位数，没有跨帧平均、拼接或虚构物理长度。另试的最小面积矩形没有显著降低这组数据波动，因此没有部署。20cm是实验识别适用范围，不是这件工件的实测长度；实际估计波动问题仍需更多原始帧与实测尺寸校核。

新增 `component_extraction.size_measurements`、`size_rejection_count` 和 `size_decisions`：记录长宽、阈值、点数，以及超长、过窄、带面边界或截断等原因。完整识别失败也带 `component_size_diagnostics`。计数针对图像帧/连通区域，不能当成实际漏抓件数。旧日志中只有汇总阻塞记录的帧，不能事后恢复逐帧真实反馈状态。

## 首轮测时与场景复用（2026-11-13）

独立入口启动时读取兼容历史日志的测时轮次，以最近一次匹配实验中观测到的最大轮次耗时作为首轮估计。源配置哈希、阶段候选、工件长度上限、保存的有效配置完整性和已记录的主机名须匹配。旧日志没有主机名时，按本地日志来自当前主机处理，并在来源字段中标明这个假设；复制到其他主机的旧日志不应作为该主机测时依据。没有兼容日志时使用源配置的 `measured_planning_initial_s`（默认0），在终端明确打印来源。此值只用于测时模式。

53.5cm/s 的 `20261113_222700_233202` 日志提供约 **0.234s** 的首轮计算耗时估计。这与约90ms的发送提前量是不同参数。估计包含候选排序等轮次开销，不只计算IK；不是固定增加机械臂运动时长，也不是耗时的保证上界。

规划失败也保存已观测耗时。空间不足的快速拒绝不会把之前较大的估计清零；下一工件首轮直接使用当前估计。人为取消的未完成工作不用于提高估计。当前采用保守最大值，不自动衰减，异常慢轮次可能使后续规划偏保守，应结合日志判断。

同一次冻结目标的测时重规划复用已安装场景及点云空间索引，并在预留时间中扣除实际省去的场景准备耗时。缓存只存活于本次规划调用；目标、起始反馈对象、模型或场景版本不匹配时不复用。下一次外层规划调用重新准备场景。每轮都重新生成带绝对时间的参考、求逆解、检查关节限值和完整轨迹碰撞，过时轨迹不会直接平移后下发。

`experiment.json` 与 `effective.yaml` 保存初始估计及日志来源。成功和失败诊断都记录 `measured_planning`；`rounds` 中的 `scene_reused_s` 表示复用所省的已测场景准备时间，`cold_equivalent_wall_s` 为加回这部分后的轮次估计，供下个新目标使用。

本次离线验证输出在 `outputs/measured_planning_update_20261113/`：53.5cm/s 的第一件使用原始第137帧重新分割、重拟合带面，保留日志抓姿/中心/速度，完整规划首轮通过，约152ms，发送截止剩约89ms；第四件完整冻结存档回放首轮通过，约142ms。两次均为1.1/0.1/0.4s。第一件抓拍时刻反馈未存档，使用规划提交时关节状态、假设张爪并由模型重建法兰，因此不能称为完全复现现场。第二、三件只有日志参考轨迹的空间约束复核通过，未完成同输入碰撞回放。没有连接设备或发送运动指令。

## 工件局部识别与离线性能对照（2026-11-14）

单帧冻结入口默认启用 `local_target_geometry_enabled: true`。已有触发像素的包围框向四边各留32像素上下文，在这个局部深度区域复用原分割、颜色投影、点云自身过滤和尺寸/开口检查。这里没有设定工件点数上限，也没有降采样。深度与RGB仍来自原曝光，局部投影使用原始像素坐标和相机内参运算。

适用范围是 `simple` 工件检测、同曝光有效触发像素、实测带面碰撞模式。其他模式沿用原完整帧检测。种子连通区域或补全后的目标触及裁剪边界、RGB轮廓不闭合、局部识别拒绝等情况会回退。另用完整原生深度检查所选RGB轮廓：即使缺失深度使目标在裁剪边界断开，也不能漏掉窗口外的低矮/断续轮廓。普通回退不能绕过原检测拒绝。

**完整带面碰撞场景仍保留。** 全图坐标转换只准备一次，局部处理直接复用切片；局部识别后的目标掩码映射回原深度坐标，再生成完整带面场景和原始像素索引。因此精细处理降到约1.2万～1.8万个深度像素，但整条流程并非只处理工件的几千个点。运行进度 `vision.grasp_geometry.frame.local_processing` 记录是否应用、局部范围、深度像素数及回退原因。

成对离线结果：`outputs/local_geometry_20261114/paired_v2.json`。使用5次实验的5个最终存档曝光，加上53.5cm/s第一件第137帧及15.3cm/s长工件第332帧，共7帧；每帧每种方法预热1次、计时5次，交替执行，使用独立模型和新曝光缓存。两组均采用20cm长度范围。计时包含完整带面场景重建，排除共同的文件读取、带面重拟合和帧复制。没有连接设备。

## 纯相机耗时分布脚本（2026-11-14）

`tools/profile_camera_geometry.py` 只打开相机，不打开CAN、不读取机械臂反馈、不规划轨迹、不发送运动指令。它处理每个取得的最新曝光；冻结区域有且只有一个候选时，运行完整局部识别和OBB抓姿计算。静止工件可以反复采样，样本数不是独立工件数。

```bash
cd /home/ubuntu22/nero_conveyor_ros2
OPENBLAS_NUM_THREADS=1 python3 tools/profile_camera_geometry.py --seconds 30 --preview --output outputs/camera_timing_trial_01
```

在有图形桌面的终端使用 `--preview` 可看RGB画面，Q/Esc停止；不加该选项则后台采样并每5秒更新 `latest_rgb.jpg`。工件应位于原冻结搜索区域。输出目录须不存在。加 `--mode full` 可单独测原完整帧流程，但不同时间的现场工况不是严格的同帧成对比较。

输出 `samples.jsonl` 保留逐帧结果，`summary.json` 分别汇总成功、拒绝和无单一候选的分布：平均值、P50/P90/P95/P99和最大值。`distributions` 包含首个样本，`steady_distributions` 排除第一个几何样本（回放时也排除每个模型的首样本）。无工件时不会用触发耗时冒充完整识别耗时。

`geometry_total` 是本脚本的检测、场景整理、中心/OBB抓姿和种子一致性检查总时间；不含正式入口的速度生成、进入时刻准入、队列和结果交付。现场相机模式另记录相机等待、深度校准、带面初始化、触发检测和完成时的曝光年龄。内部拆分为坐标准备、RGB投影、轮廓检查、工件过滤、机械臂几何准备/点过滤和抓姿生成。`wall_s` 是包含子调用的墙钟时间；`exclusive_wall_s` 扣除已测子调用，各内部项与 `geometry_total.exclusive_wall_s`（剩余未细分工作）可以相加为总时间。不同项的P95不能相加当作总P95。

同时记录线程CPU时间。墙钟减线程CPU时间还可能包含原生库其他线程的计算，不能直接解释为操作系统调度延迟。计时包装会引入少量开销。

由于完全不读取机械臂反馈，自身过滤使用配置等待位及张爪假设；实机姿态不符时不能用该过滤结果证明真实工件识别正确。脚本在私有内存配置中使用独立实验相同的20cm长度上限，不修改现场文件。重复等待位缓存不能代表运动中反馈角变化的开销。

离线自检使用历史53.5cm/s首件/末件和长工件帧，每帧重复10次，记录在 `outputs/camera_geometry_profile_20261114_replay/`；这是保存画面回放，不是新的现场采样。

逐次通过记录可加 `--passages 5 --declared-speed-cm-s 53.5 --seconds 180`；带速仅作操作者声明的元数据，不测量或控制带速。连续0.7秒无候选后结束一个候选事件，保存事件首帧与首次完整识别截图。**这只是候选事件计数，不等于工件数量**：放件手部进入搜索区也可能触发。因此实际逐件实验必须核对截图，并保留失败、额外事件与记录间隙，不能只按计数器声称完成5个独立工件。`passage_results` 和逐帧 `passage_id` 用于追溯。

## 每次抓取实验的自动归档（2026-11-14）

后续实验默认保留每个冻结目标和每次规划的证据，用于论文统计及离线回放。真机抓取入口自动启用，原启动命令不变，不依赖 `--preview` 或 `--record-rgbd`。纯相机耗时脚本仍使用其独立记录格式。

每个运行的 `hardware/experiment/` 内有独立编号文件，不会被下一件的预览覆盖：

- `geometry_input.npz`：单曝光几何任务的原始冻结输入，包含已标定RGB-D、原带面参数、候选像素和配对反馈。识别失败也保存；不能对其中深度再次标定。
- `geometry_result.json`：该输入的识别结果、失败原因和耗时诊断。取消与识别拒绝按诊断区分。
- `target.npz`：每个成功识别目标的点云、候选抓姿、原场景点云/像素、OBB、带速、曝光时间和配对关节反馈。之后规划失败或跳过也保留。
- `planning_input.json`：每次规划使用的实际或名义起点、反馈原时间戳、原曝光身份、提交时刻和规划耗时预留；重算分别编号。
- `plan.npz` / `planning_failed.json`：完整曲线的分段多项式系数与节点、参考轨迹参数、认证诊断、失败候选及耗时。规划成功不等于已经下发或实物抓取成功。
- `configuration/`：运行时配置、运动上限及相机/TCP标定和示教文件副本、哈希。
- `index.jsonl` 与 `summary.json`：文件关联、保存数量、丢弃/写盘错误及完整性状态。

实际下发角、反馈角、夹爪反馈、执行/恢复事件仍在原来的 `cycle_*/execution_trace.npz`、`cycle_*/events.json` 和 `events.jsonl`，通过目标身份与主机单调时钟关联。冻结前的无候选、反馈缺失等仍由原视觉诊断记录；`--record-rgbd` 是额外的2Hz画面采样，不是全帧录像，也不保证覆盖所有经过但未识别的工件。

记录使用独立有界后台写盘队列；生产者只复制必要输入，不等待磁盘。队列溢出、写盘失败、退出时未写完都明确标记记录不完整，不能把不完整实验当成完整样本集。冻结输入复制与后台I/O仍有开销，需要在下一轮现场日志里观察，不承诺零耗时。结束时终端打印归档完整性和条数。

实际放行数量、工件类别、掉落和实物入框结果需现场确认；传感器夹持确认与人工实物成功标签保持分开，未确认记为未知，不自动计作成功或失败。
