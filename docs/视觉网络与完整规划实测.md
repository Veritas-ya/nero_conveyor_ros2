# 视觉网络与完整规划实测

2026-10-27 的离线诊断使用 MuJoCo 渲染 RGB-D，物体从仿真传送带起点进入。相机采集同帧机器人状态，不使用物体真实位置、真实速度或接触状态作为感知输入。Nero7 检测关联及 XY 卡尔曼滤波提供速度，GraspGen-X 使用真实网络权重产生候选；网络推理与同帧原有机器人自身和场景点云过滤并行。选择的抓姿、场景和持续更新的视觉跟踪绑定到原 `full_preplanned` 连续规划上下文，随后实际提交完整规划请求。图像使用原生模拟 RGB-D，**本次没有运行 Fast-FoundationStereo**。

诊断只运行规划，不把策略动作发给 MuJoCo。规划失败时不发送机械臂或夹爪命令；不证明物理夹持、抬升、投放和回位。真实视觉执行入口和 ROS 设备闭环仍未完成。

两次捕获和调度并非完全相同，不能据此评估提前量对耗时或成功率的影响。网络和场景过滤并行，不应相加当作总耗时；加载和预热发生在仿真任务计时之前。未产生可执行轨迹，实际执行耗时和抓取成功率均无结果。仿真提前量是参考轨迹的候选，不是经实测的硬件延迟模型；它必须通过原完整几何和动力学认证才能使用。本轮在生成可认证的完整轨迹之前已被拒绝，不能称为提前补偿已物理验证。

不含提前量的一次记录有 TCP 速度、关节余量、IK 和接触截止时间拒绝；提前量一次记录有 TCP 速度和 IK 收敛失败。不能放宽这些门槛来宣称成功。下一步需要在已有筛选标准下改进可达抓姿选择及拦截时刻与完整轨迹联合求解，并缩短场景准备和规划交付时间；通过完整证书后再连接仿真动作、闭合反馈、物理夹持、料箱及返回任务。

复现（外部 CUDA Python 环境和官方权重自行安装；不需要访问旧项目源码）：

```bash
cd /home/ubuntu22/nero_conveyor_ros2
export NERO_GRASPGENX_CHECKPOINT_DIR=/absolute/path/to/checkpoints/release
export PYTHONPATH="$PWD/src/nero_core:$PWD/src/nero_bringup"
export MUJOCO_GL=egl OPENBLAS_NUM_THREADS=1
/path/to/cuda-python tools/probe_measured_network_scene.py --seconds 25 --output /tmp/nero-visual-plan.json
```

该命令中使用 100 ms 仿真提前量，未认证时返回非零退出码。完整记录分别在 [无提前量](measured_visual_20261027/nominal.json) 与 [提前量诊断](measured_visual_20261027/advance.json)。本轮相关离线回归 567 项通过；`nero_core`、`nero_interfaces` 和 `nero_bringup` ROS Humble 构建通过，物理 launch 参数检查通过。没有连接真实设备。
