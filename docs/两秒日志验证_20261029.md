# 两秒入口日志验证（2026-10-29）

本轮只改日志及诊断，未连接真实相机/CAN，未发送真实机械臂命令，未修改速度、加速度、两秒策略或闭合阈值。此前18:29取消运行时未保存的等待信息无法追回；旧记录保持原样。

## 实现与证据

- `diagnostics.py`：逐观测原因计数、每类原因最近上下文、视觉阶段/操作耗时、有界后台JSONL写入及每秒进度采样。
- `vision.py`：为各个跳过观测的分支记录实际数值；保留原通过条件。包含反馈缺失/时间偏差、带面、轨迹和测速、上游门槛、检测与关联、观测年龄及视觉异常。
- `planning.py`：记录场景准备、当前候选及IK路径点、剩余预算、多项式/几何检查和已结束候选结果。
- `execution.py`：关键事件通过非阻塞队列持续记录，日志回调异常不改变既有控制流程。
- `main.py`：设备启动前创建日志；启动失败、没有任务就取消、规划失败及SIGTERM都收尾保存摘要。记录使用的源码/配置哈希和软件运动约束，避免混用不同次运行的参数。

输出说明见[日志诊断](两秒日志诊断.md)。验证证据位于 `runs/two_second_logging_validation/`；其中 `cases/` 全部是**离线测试替身和故障注入记录**。入口替身测试会调用生产 `main --execute` 分支，但设备模块已替换，记录中的 `mode: hardware` 只表示选择了该代码分支，不能解释成实际连接硬件。
