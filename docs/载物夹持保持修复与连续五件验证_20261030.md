# 载物夹持保持修复与连续五件验证（2026-10-30）

当前修复版在同一MuJoCo进程内，连续完成随机T-LESS工件 **5/5** 的视觉测速、OBB抓取、跟随闭合、实际夹持与抬升、同框稳定投放、返回等待位。每件返回后再生成下一件；末次还独立复核五件均在框内、有承重支撑且脱离手指。类别顺序12、6、9、0、14仅指生成模型ID，不是视觉分类结果。

## 失败复现与判断

在原8 rad/s²通用参数下，仅增加诊断字段后复现失败：确认开口54.790 mm，异常时57.853 mm，变化 **3.063 mm**，超过原3 mm门槛；电机仍请求2 N。物体相对TCP产生约1.733 mm位移及3.001°转动，连续两帧失去左指接触。独立物理接触检查未发现载物撞料框、带面或机器人非手指部位。

原转运路线已经有平滑处理，轨迹也满足机械臂8的能力边界；第一件参考关节加速度峰值约5.589 rad/s²、转运时长1.95 s。把机械臂能力边界直接作为载物时间参数化请求，会产生当前2 N夹持未能维持的运动。降低该阶段运动强度、保持抓姿、力、材料与判定后，故障不再出现。这是本场景的对照结果，不是经过厂家实测的通用载物能力模型。

## 修改

1. 新增共用 `motion_profile.py`，把设备能力/标准运动参数与载物请求分开。现场全局边界仍为七轴8 rad/s²，速度100%请求、每轴2 rad/s；抬升和转运显式采用此前成功仿真使用的七轴2 rad/s²。空载返回使用标准参数。此2是载物运动请求，来源明确标记为MuJoCo验证记录，不是厂家上限。省略载物配置时仍继承全局参数；非法、无来源或高于全局边界的载物请求在设备连接前拒绝。
2. 生产路径规划和仿真 `plan_smooth_leg` 共用同一参数选择；完整关节曲线重新时间参数化，保留静止q/v/a端点，重做原几何及载物碰撞检查。第一件转运时长由1.95 s变为3.33 s，峰值降到约1.917 rad/s²，仍执行完整投放位姿和已规划路线。
3. 真机100 Hz发送器、最终实际发送采样、跨阶段指令历史也使用所选载物参数。设备8的能力没有被改写，实际发送异常仍拒绝；阶段切换不重置发送历史。
4. 原开口、受力和连续确认条件保留：3 mm开口变化保护、2 N闭合请求、0.2 N受力门槛、原0.4 s确认。开口异常现在记录确认宽度、实际宽度、变化及当时受力。没有添加抓取辅助、焊接、理想夹持或工件状态重置。
5. 增加只读物理诊断：工件相对TCP位姿、两侧接触力和非手指接触。它们用于结果核验，不给视觉测速或抓姿提供真值。
