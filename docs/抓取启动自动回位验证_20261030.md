# 抓取启动自动回位接入与验证

2026-10-30 将独立回位脚本接入 `two_second_pick` 启动流程。本轮只修改代码并做离线验证，没有连接相机、机械臂或 CAN，没有发送真机命令。

## 行为变化

此前启动时关节偏离等待位会立即以 `standby_joint_mismatch` 退出。现在仅在显式 `--execute` 的启动恢复阶段，先检查原有空爪条件和正常设备反馈，若最大关节偏差超过 0.005 rad，使用厂家 `move_j` 平滑返回配置等待位。到位仍要求误差不超过 0.005 rad，并在新的反馈时间上稳定 0.1 秒；默认回位超时 15 秒，速度读取 `pick_settings.speed_percent`（当前现场配置为 100%）。

回位后恢复原抓取配置模式（当前为 `js`），再次核对关节与夹爪，然后才启动相机与视觉测速。已在等待位时跳过回位目标和速度命令。回位期间不产生冻结视觉目标，不会把回位用时带入一个已经接纳的旧抓取预约。

夹爪带载、宽度不符、关节反馈无效时不发起回位。已尝试发送关节目标后若超时、取消、时钟重置或反馈/发送异常，共享逻辑尝试电子停止，并终止启动流程，不自动开爪、归零或使能。已接纳目标之后再次发现机械臂起点偏离，仍拒绝执行；正常抓放周期结束时的认证返回路线保留。

## 实现与追溯

- `nero_core/move_to_wait.py`：独立 CLI 与启动恢复共用 `execute_return_wait`，保留单次 J 目标、原反馈到位检查和异常停止逻辑。
- `nero_core/two_second/startup.py`：检查是否需要回位、使用已加载配置和模型、复用现有设备连接/发送所有权/取消事件、到位后恢复抓取模式。
- `nero_core/two_second/main.py`：在相机启动之前调用恢复逻辑；检查模式显示回位策略，不打开设备。任务来源哈希加入共享回位模块。
- `nero_core/two_second/execution.py`：启动恢复可单独检查夹爪条件；任务执行检查默认仍要求等待位，另明确拒绝非有限关节/夹爪反馈。

每次抓取仍只创建一个厂家设备适配器，没有运行回位子进程或第二个 CAN 客户端。`startup_return_wait_*` 日志记录跳过、发送、反馈、到位和失败；`summary.json.startup_return_wait` 保存结果。`startup_return_wait.total_wall_s` 是设备启动阶段的一部分，不能重复相加。

## 验证

165 项离线回归通过（8.86 秒），涵盖独立脚本、启动恢复、抓取入口、诊断、平滑轨迹迁入和既有真机/仿真门控。使用虚拟设备及部分可控时钟，证明调用顺序和异常处理；不代表真实机械运动、物理夹持或场景避障通过。

针对启动入口验证：初始不在等待位时只有一个关节目标，调用顺序为 `js → j → js`，使用同一个虚拟设备，到位后才创建相机；已在等待位不发送回位命令；发送失败和取消走停止路径且不开相机；夹爪带载或闭合时不发起回位；接纳目标后起点漂移仍拒绝规划。另覆盖回位超时、陈旧反馈、时钟重置、驱动故障、部分发送和取消。

证据目录为 `runs/startup_return_wait_20261030_142712/`，包括修改前文件、SHA-256、pytest XML/日志、ROS 构建日志、安装入口只读检查及文件一致性记录。工作区无 Git，来源版本以该目录 manifest 中的文件哈希为准。

## 使用和边界

原抓取命令保持不变，详见[真机接入](两秒策略真机接入.md)。只检查配置不会产生任何回位动作；仅 `--execute` 才允许自动回位。回位使用厂家内部规划，未对其内部路径做主机 q/v/a 或场景碰撞认证，沿用[独立脚本的范围](机械臂返回等待位.md)，不能据此声称任意起始姿态都可避障返回。
