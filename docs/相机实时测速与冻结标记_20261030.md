# 相机实时测速与冻结标记

共享相机预览现补齐生产测速数据：青色显示沿标定传送带方向的卡尔曼速度、跟踪ID及待确认状态；黄色显示实际接纳目标的冻结速度，并在RGB、冻结曝光及3D视图标出冻结时的测量位置。黄色位置固定在原始观测位置，不跟着物件移动，也不是OBB抓姿中心。

启动方式保持不变，真机抓取命令使用 `--execute --preview`。已运行的旧预览进程需要关闭后重新打开才能加载新显示代码；仅关闭窗口不会停止抓取。只读查看某个运行目录：

```bash
cd /home/ubuntu22/nero_conveyor_ros2
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 run nero_core camera_grasp_view \
  --config /home/ubuntu22/nero_conveyor_ros2/install/nero_bringup/share/nero_bringup/config/two_second.hardware.legacy_observed.yaml \
  --follow-run /home/ubuntu22/nero_conveyor_ros2/runs/two_second_hardware/本次目录
```

共享模式只读取抓取程序已有的相机帧和Nero7结果，不另开相机、不重新测速。滤波仍按原相机观测更新，画面传输维持原来的约5Hz；图像和测速结果都带曝光序号与时钟代次。只有与图像匹配的实时轨迹才投影在图上；冻结标记还核对相机标定、序列号和时钟代次。选择其他目标的历史碰撞时，不把当前目标的黄色标记叠加进去。

冻结值来自规划实际使用的速度和观测位置，后续实时速度变化不会改写它。滤波预热数值显示“待确认”；超过原配置的观测年龄显示“末值（未更新）”；回放显示“历史卡尔曼”，不冒充实时。独立相机模式同样显示实时滤波值及黄色冻结标记。

旧运行目录的 `target.npz` 没有测速字段时，窗口可从该目标已有的 `qualified_target` 和 `planning_submitted` 事件恢复冻结值与冻结位置。没有保存的逐帧速度不会被补造。已在 `test_20261030_201439_824446187` 的只读回放中恢复ID118、8.15 cm/s及原始冻结位置；这只是显示已记录值，不代表该速度准确。

本轮仅补显示与数据共享，没有改变卡尔曼算法、冻结门槛、轨迹或避障参数。现场测速偏差和ID连续性问题仍需独立修复。本轮未连接相机/CAN或发送真机命令。

离线验证记录在 `runs/speed_display_20261030_204309/`，包括新旧数据传输、曝光/时钟隔离、实时值与冻结值分离、黄色像素投影及历史真实曝光截图。
