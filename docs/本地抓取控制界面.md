# 本地抓取控制界面

界面将 CAN、机械臂使能、相机规划和真机抓取作为独立操作。启动网页本身不打开相机、不连接机械臂，也不使能或移动设备。

## 启动

无需重新构建或覆盖现场安装目录。在当前工作区执行：

```bash
cd /home/ubuntu22/nero_conveyor_ros2
sudo -v
OPENBLAS_NUM_THREADS=1 python3 tools/control_panel.py
```

打开 <http://127.0.0.1:8765>。`sudo -v` 仅用于同一启动终端内后续 `can0` 设置的权限缓存；网页进程仍以普通用户运行。若 can0 已经就绪，可以省略。密码不经网页传输或保存。权限缓存失效时，界面会报告设置失败；在原终端结束界面服务，再运行以上命令。服务只监听本机地址。

如需只读查看已使用 `--preview` 或 `--web-preview` 启动的运行，可以点击“查看已有运行”。也可在启动界面时指定工作区内的运行目录：

```bash
OPENBLAS_NUM_THREADS=1 python3 tools/control_panel.py \
  --observe-run /home/ubuntu22/nero_conveyor_ros2/runs/实际运行目录
```

只读查看使用已有原子预览文件；“结束查看”只结束网页查看，不会停止原终端的设备程序。运行结束或帧龄过大时，画面标为历史画面。

## 操作

1. **启动 can0**：检查接口，以 1 Mbit/s 启动。已正常启动的接口保持原状态；没有找到 USB-CAN、权限不足或总线异常会在界面报告。
2. **机械臂使能**：显式调用厂家七轴使能，随后使用原适配器验证真实驱动、关节、法兰及夹爪反馈。使能操作不发送运动、开合或归零目标。夹爪仍需处于现有程序要求的已使能 width 模式；检查未通过会报告具体原因。使能后退出不会自动失能。
   **打开夹爪**按钮位于其下方：空闲时显式张开到配置开口（当前100mm），沿用原张爪1N请求。取得控制权并确认真实反馈与关节停稳后，发送一次张爪目标，以新夹爪反馈持续150ms处于目标2mm以内确认完成。操作不自动使能、不发送机械臂关节目标，也不归零；设备被占用、反馈异常或动作未确认时会报告原因。
3. 选择算法，填写**实测带速，单位 cm/s**。43.5 是初始示例值。带速上限读取所选 YAML，并在后端再次校验。
   界面会在 `runs/control_panel/operator_options.json` 记录最近填写的算法、带速和连续选项，刷新或重启后恢复表单；不会自动恢复设备动作，也不改写现场YAML。
4. **仅相机规划**：使用原 `FixedFreezeWorker`，按当前配置的 70～65 cm 单帧冻结区获取点云并计算模型路径；不连接 CAN。使用“下一件”重新等待新的曝光。匹配版的相机规划未接入此按钮，请选择两个单帧模式之一。
5. **开始真机抓取**：调用原抓取入口。选中连续抓取时循环执行；关闭时执行一次。启动、运动认证、示教投放/返回、恢复和反馈检查仍由原执行器处理。

“停止运行”向本界面启动的进程发送正常取消信号，等待原程序释放资源。它不是硬件急停，也不会强制杀死发送器或使机械臂失能。停止完成前不能启动下一任务。关闭网页不会自动停止已启动任务，重新打开同一页面可以继续查看；在启动终端按 Ctrl+C 会请求结束界面持有的任务。

外部抓取程序持有原运动租约时，界面禁用设备操作。需要在原终端停止该程序后再从网页启动新任务；网页可以直接只读查看它已经共享的画面。

## 画面与数据来源

实时 RGB、冻结原始曝光分别展示，冻结点云与 TCP 轨迹使用机器人基座坐标系。三维视图支持拖动旋转、滚轮缩放、适应视图、俯视及图层开关。场景点云仅为显示抽样，不作为新增的碰撞认证。

真机通过新增的 `--web-preview` 共享现有 `VisualArchive` 预览文件，不弹出 Qt，也不重复打开相机。原来的 `--preview` 行为保留。网页只有在目标身份和曝光编号同时一致时才展示对应路径，旧目标路径不会叠到新点云上。

相机模式的初始机器人状态是配置等待位，模型路径不代表真实抓取成功。模型已生成但错过发送截止会单独显示；真机路径图也只代表规划输出，实际执行结果以真实反馈和运行记录为准。

网页任务记录保存在 `runs/control_panel/`，每次使用独立目录。原抓取程序的 events、summary、示教和逐次轨迹记录保留。当前 YAML、标定、带速来源、示教样本、时序和运动约束不由界面改写；带速只覆盖本次运行。

## 离线演示与验证

```bash
OPENBLAS_NUM_THREADS=1 python3 tools/control_panel.py --demo --port 8766
```

演示模式明确标注为模拟，相机、点云、轨迹和按钮状态均不访问设备。它不能作为设备联调或真机抓取验证。

后端只接受既有操作和算法枚举，以参数数组创建子进程；不接受任意命令、配置路径或 shell。写操作要求本机 Host、同源请求及本次服务令牌。

如果以后构建 ROS 包，也可使用新增入口，显式指定工作区：

```bash
ros2 run nero_core grasp_control_panel --workspace /home/ubuntu22/nero_conveyor_ros2
```
