# 以搬运示教起点的 TCP 方向排序 OBB 抓姿

现场配置 `obb_grasp_orientation_reference: taught_transfer_start` 优先使用与当前
已加载的搬运示教轨迹**第一个关节样本**的 TCP 方向更接近的 OBB 抓姿。方向由
当前机器人模型及配置的法兰到 TCP 变换做正运动学得到，和目标 OBB 抓姿处于同一
基座坐标系；比较使用三维旋转差，而不是逐项比较欧拉角。先选当前 OBB 的两种
短轴、180° 对称姿态，计算各自差角后排序。较近姿态规划失败时仍尝试另一个；
每条候选仍要完成原有的时序、逆解、关节及几何检查。

读取参考方向时临时设置模型到示教起点，读取后恢复为真实反馈关节；这不发送
设备命令。计划日志 `trajectory_diagnostics.grasp_orientation_reference` 记录
示教文件、哈希及两候选的方向差，`selected_input_grasp_index` 记录最终选择。
没有显式配置时沿用当前 TCP 方向；显式选择示教起点但未加载示教段时拒绝规划。
本配置使用的是已经截短的搬运段起点，不是原始未截短示教段的第一个点。

对 2026-11-05 11:12:20 保存的一次真实观测，仅做方向离线对照：候选 0 和 1
相对当前起点 TCP 的角度分别约 56.7°、124.0°，相对搬运示教起点则分别约
130.8°、50.3°。排序从候选 0 改为候选 1；这不是该候选可以达到或完成抓放
的证明。新策略已通过离线模拟规划及回退测试，未进行真机动作验证。
