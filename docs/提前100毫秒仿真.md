# 命令参考提前 100 ms：仅物理仿真

`physics_sim` 和 `physics.launch.py` 当前默认在**仿真**中请求命令参考提前 0.1 s。设置 `--simulation-command-advance-s 0` 或 launch 参数 `command_advance_s:=0` 可运行名义轨迹对照。输出目录须不存在：

```bash
cd /home/ubuntu22/nero_conveyor_ros2
source /opt/ros/humble/setup.bash
colcon build
source install/setup.bash
ros2 launch nero_bringup physics.launch.py output:=/tmp/nero-advance-01 command_advance_s:=0.1
```

这不是证明网络或硬件有 100 ms 延迟的测量，也不改变实际发送时间戳。它使用未来 100 ms 的名义关节轨迹生成候选命令曲线：起步平滑接入，闭合阶段逐渐退回，抬升保持原轨迹。候选必须满足原关节位置、速度、加速度、已有 jerk 限制，并经过原命令曲线的时间采样、场景/目标碰撞及 TCP 速度认证；若未通过则整个规划失败，不退回未提前轨迹。实际反馈、场景复查和闭合门控没有放宽。该实验仅支持完整连续路径，不支持与 contact-handoff 或响应模型混用；那些诊断需要显式设 0。

## 同条件对照

固定 seed、0.04 m/s 带速、类别 0、出生 x=-0.4 m，各运行一次 16 s；这是便于快速观察的仿真输入，默认上游出生位置不变。两次路径均获得原规划认证。名义轨迹规划约 0.433 s，提前曲线及额外认证约 0.867 s。模拟时刻 9.856 s，同一时刻的名义轨迹与反馈末端位置误差：未提前约 **12.58 mm**，请求提前 100 ms 约 **2.94 mm**。

但提前实验在 9.86 s 仍以 `full_pick_feedback_or_live_geometry_invalid` 进入恢复，名义对照约 9.98 s 进入恢复；两轮都未完成闭合和抬升。提前实验终止时记录的预发送命令与反馈位置距离约 **22.08 mm**，略大于已有 **22 mm** 门控；这是另一个量，不应与同一时刻的名义跟踪误差混为一谈。不可据这一次判断抓取成功率、长期性能或真机延迟，也不能通过放宽门控来掩盖问题。

数据摘要见 [对照证据](command_advance_100ms_evidence.json)，原始输出位于 `/tmp/nero-full-preplanned-only-02/continuous` 和 `/tmp/nero-full-advance100-01/continuous`，可能由系统清理。视觉仍使用模拟历史观测与目录抓姿，未运行网络，未连接设备。下一步需检查提前参考与实际反馈门控之间的冲突，并在不放宽认证前提下重新求解预约及响应；实机应用前必须独立测量设备响应和时钟。
