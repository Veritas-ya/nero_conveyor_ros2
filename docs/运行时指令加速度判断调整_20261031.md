# 运行时指令差分加速度判断

按用户要求，现场配置将 `runtime_command_acceleration_check_enabled` 设为 `false`。`two_second` 当前任务在发送时不再根据关节目标位置与发送间隔的差分加速度拒绝命令，包括首个点的差分加速度判断；关节速度和其他发送检查仍启用。旧调用或未明确配置此项的其他现场配置仍沿用原来的加速度检查。

规划曲线仍在生成时检查位置、速度和加速度；空载 8 rad/s²、载物规划 2 rad/s² 保持不变。规划曲线通过不能证明实际发送时差分加速度合规，也不能证明真实关节加速度合规。

用户表示厂家会在加速度过大时自行急停，但当前没有核实本设备 v121、`move_js` 路径是否如此。厂家 SDK 对 `move_js` 明确说明没有平滑和轨迹规划。此轮没有连接 CAN/相机、查询固件、发送运动或验证急停；不应将关闭上位机判断理解为固件保护已经验证。最近碰带的原因及 TCP、带面标定仍需独立核查。

使用上次故障记录进行离线重放，在当前逐关节速度限制下，该候选不再被差分加速度判断拒绝；模拟超过速度上限仍被拒绝。248 项相关离线测试、ROS 两包构建、只读配置检查通过。ROS 安装配置为 false；脚本下次运行会使用此设置。
