# GraspGen-X 启动预热与结果对照

2026-10-27，在已经迁移的 Nero7 视觉物理诊断入口中，网络模型加载后、仿真主计时开始前，使用固定种子生成 512 个有限合成点，仅运行一次网络推理做 GPU 内核预热。预热输出不进入目标识别、抓姿选择、控制或评分；每次真实请求仍由原 backend 使用请求自己的种子重新初始化随机数。模型和检测器参数、原候选筛选、碰撞、反馈及闭合条件没有修改。

两轮都为 seed 1543、1 个类别 12、x=-1.28 m 上料、带速 0.1 m/s、25 秒仿真。渲染点云的输入 SHA-256 一致；两个 `.npz` 中 512 个姿态和评分逐值一致。两轮各一次，系统负载和调度未控制，仅说明本机两次记录，不能作为稳定的统计收益或新的物理成功率。

预热降低了这两次记录中的首次目标推理耗时，但整轮没有加速。输入曝光到接纳间包含等待、候选检查和调度，与网络推理存在包含关系；不能将其重复加总。预热在仿真计时前完成，加载、预热和单件计算分开记录。两次的首个原连续拦截均因固定捕获时刻不满足关节速度/加速度或 jerk 限制而拒绝；后续候选未保持实时几何或反馈范围，最终都以 `ik_unreachable` 恢复，未夹持和投放。不能把候选选中当完整轨迹认证通过。

旧轮 751 次配对 RGB-D 渲染耗时合计约 5.985 s；视觉帧捕获到子进程处理完成的墙钟 P50/P95 为 18.45/36.52 ms，期间与其他工作可能重叠。这些统计不解释全部墙钟差距；当前没有足够证据把实时不足归结为单一模块，也不能用相加的阶段数作为完整墙钟。后续需以实际完整时间分段、同输入交替对照定位同步渲染、控制、写盘、进程调度与 GPU 竞争。

71 项视觉及预热相关测试通过；ROS 包重新构建成功。记录和可复现的两次比较见 `vision_migration/warmup_comparison.json`、`warmup_20261027/array_comparison.json`；新运行原始结果在 `../runs/vision_network_warm_20261027/`。仍使用独立历史视觉仿真控制策略和 diffusion 网络；最新 full_preplanned/P1-A、GraspMoE 与 Fast-FoundationStereo 尚未连成该视觉仿真的端到端主链，物理成功率和两秒目标仍未验收。
