# 真机冻结点云与轨迹画面

真机抓取程序使用 `--preview` 时，共享已有 RGB-D 采集，不额外打开相机或 CAN。抓取程序提供同一冻结曝光中的工件点云、OBB、跟踪速度与抓姿候选；规划器返回轨迹后，把结果放入后台队列，由独立标定模型将七轴关节轨迹做正运动学。每条路径按目标 identity 和曝光帧配对；不匹配时不叠加。归档和窗口失败只报告可视化错误，不成为机械臂执行输入。消息经有界队列和原子文件交换，点云不经 JSON。

右侧颜色：绿色是接近，青色线是闭爪跟随，黄色线是减速；青色点是冻结工件点云，紫色点是用冻结速度推算的接触时刻工件，白色是预测接触抓姿。轨迹是**规划关节曲线的 TCP 正运动学**，不能证明已经发送或机械臂实际上沿该轨迹运动。规划器返回不等于执行器已交付；界面明确标明这一点。

实时画面随常规真机程序的 `--preview` 启用。它是只读显示，不是运动开关。若把 `--preview` 加在含 `--execute` 的现有命令里，该命令仍会执行真实抓取，启动前应确保现场准备完毕；需要无人移动的预览时使用既有相机独立预览模式，该模式的路径以假设等待位和冻结规划时钟计算，不是实际实时抓取轨迹。

`runs/visualization/real_path_replay/` 是从 `runs/two_second_hardware/sync_20261031_210337` 生成的历史回放：目标点云和曝光采用原运行 `preview/target.npz`；曲线采样该次 `execution_trace.npz` 中成功发送的关节位置，用标称 TCP 正运动学计算。该路径是历史已发送指令的可视化，并非完整规划曲线的保证，也不是实际反馈轨迹。原运行记录的标称 TCP 和深度标定文件 SHA256 均与本次读取的文件一致，仍不能替代实际 TCP 标定。该次预设带速约 4.15 cm/s，与当前带速无关。回放不连接相机和机械臂。

测试：`tests/test_collision_visualization.py`、`tests/test_speed_overlay.py`、`tests/test_belt_collision_scope.py` 共 32 项通过，其中包含目标切换时禁止显示旧轨迹、基于独立模型 FK 和无设备的回放；单次历史真实曝光回放已通过 Qt 窗口核对。未执行实时硬件测试。可视化使用 20 Hz 左右采样，不改变或替代实际控制频率与认证采样频率；允许图形队列在负载高时丢弃显示记录，执行不等待绘制。
