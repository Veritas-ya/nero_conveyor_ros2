# 离线场景碰撞对照

`offline_scene_collision` 只重放保存的关节状态与场景碰撞触发点，不导入或连接相机、厂家设备或CAN，不生成/发送轨迹。真机原有碰撞判定保持启用；本工具的 `record_only` 不被真机入口读取。

配置 `offline_scene_collision.yaml` 声明 `scope: offline_saved_state_only`，可选择 `scene_collision_action: reject` 或 `record_only`。两种模式都会计算并保存原场景告警；后者仅对离线保存状态忽略场景拒绝，仍记录关节范围、自碰撞等模型检查结果。将此配置传给真机入口会在任何设备导入前被拒绝。

```bash
cd /home/ubuntu22/nero_conveyor_ros2
source /opt/ros/humble/setup.bash
source install/setup.bash

OPENBLAS_NUM_THREADS=1 ros2 run nero_core offline_scene_collision \
  --run /home/ubuntu22/nero_conveyor_ros2/runs/two_second_hardware/test_20261030_201439_824446187 \
  --output "/home/ubuntu22/nero_conveyor_ros2/runs/offline_scene_comparison_$(date +%Y%m%d_%H%M%S_%N)"
```

20:14:39记录的两个候选都可在原机器人模型中复现 `nero_link6_collision` 场景告警；只忽略场景点拒绝时，这两个保存姿态的其余模型检查通过。这只说明该处的软件拦截来自记录中的场景点，不证明那个点是自体残留，也不证明完整轨迹可执行。

原记录只包含触发点及相应关节角，没有全量原始场景点云；工具不会伪造缺失场景、跳过其他失败后声称规划成功，也不把孤立状态通过标为真机执行许可。输出 `comparison.json` 明确设置 `trajectory_computed: false`、`full_scene_certified: false` 和 `hardware_execution_authorized: false`。
