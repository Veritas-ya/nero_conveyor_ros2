# 执行时延波动与有限抓取区间实验

日期：2026-11-11。已实现可选的残余时延窗口检查、离线辨识和独立配置生成，尚未连接设备验证。本轮功能开发未写现场配置、安装目录、90 ms提前量、示教或限值。初次保护检查的20个文件哈希均一致；收尾时发现两份现场YAML的等待位被外部工作更新，本轮保留该更新，18个其他保护文件仍一致。两次检查分别保存在 `outputs/execution_delay_window_20261111/protected_file_verification.json` 和 `protected_file_final_check.json`。离线回放固定使用更新前保存的独立配置副本；当前现场等待位不等同于本轮回放起点，90 ms仍保持。

## 本轮实现的范围

新增配置字段 `execution_delay_window`，只支持现有 `smooth + synchronized` 策略。未声明该字段时，仍使用原逻辑，不插入新的默认参数。

| 模式 | 规划行为 | 执行前行为 |
| --- | --- | --- |
| 无字段 | 原逻辑 | 原检查 |
| `shadow` | 原抓取区间；附加计算“若采用时延范围，是否满足窗口” | 核对记录与轨迹/配置一致，不按附加窗口结果拒绝 |
| `experimental` | 使用残余时延收缩后的区间重新计算接入；误差预算或区间不可行则拒绝该候选 | 没有匹配记录、轨迹/配置已改变、时钟起点不符时拒绝发送 |

两种可选模式都继续运行原有IK、关节q/v/a、名义几何、反馈新鲜度、发送时窗、版本/身份和实际发送检查。不延长100 Hz发送检查时窗，不自动改90 ms，不平移一条已失效轨迹。

该功能处理的是**以等效运动滞后为代理的有限抓取区间约束**。它不是对CAN发送线程迟到的修复；旧日志中的“实际发送超出本次几何检查时窗”仍由原发送器拒绝/重试规则处理。

## 为什么只加残余范围

实测指令曲线为 `u(t)`，反馈曲线近似为 `u(t − τ)`。现有发送器已提前 `a = 90 ms` 采样参考，因此模型中的残余时间偏移为：

`δ = τ − a`。

不是在90 ms之上再加85–90 ms。软件耗时、线程排队、实际发送以及发送后到反馈的滞后也不能不加区分地重复相加。

在同步/跟随参考阶段，以名义沿带坐标 `x` 和正向速度 `v` 表示，模型中对应的目标坐标范围为 `x + vδ`。给定原区间 `[L,U]`，为了同时容纳名义参考和延迟后的目标参考，使用：

`L_eff = L + v × max(0, −δ_min)`

`U_eff = U − v × max(0, δ_max)`

并检查 `||velocity|| × max(|δ_min|, |δ_max|)` 不超过显式指定的位置误差预算。三维工作区还检查同步起点、接触点和跟随终点在时延范围两端的目标参考位置；名义整条接近/跟随/减速曲线仍通过原几何检查。

例如用原14次近接触拟合的83.70–94.07 ms，并人为额外留出两侧各5 ms试验余量，得到78.70–99.07 ms。减去90 ms后为 **−11.30至+9.07 ms**。按0.405 m/s计算，原沿带区间 `[-0.20,0.38] m` 收缩为约 `[-0.19542,0.37632] m`；模型中的位置误差上界约4.58 mm。

这里额外5 ms和示例5 mm误差预算都是**待验证的实验设计值**，不是实测物理容差或置信界。工具要求显式提供它们，不自动从成功率或夹爪开口猜测。

## 辨识范围与真实数据

已有14次辨识来自 `runs/hardware_fixed_freeze_20261111_144606`：设定速度0.365 m/s、提前量50 ms；近接触等效滞后中位数85.17 ms。新的配置副本不会把50 ms训练提前量直接照抄到当前运行。

本轮又对 `runs/hardware_tracked_20261111_165216` 的90 ms、0.405 m/s日志进行相同符号约定的辨识，使用实际发送位置和每轴反馈接收时刻，固定近接触拟合窗0.75–1.20 s：

| 周期 | 拟合等效滞后 | 关节拟合RMS | 说明 |
| --- | --- | --- | --- |
| cycle_001 | 82.607 ms | 0.003790 rad | 有足够运动数据 |
| cycle_002 | 82.972 ms | 0.004510 rad | 有足够运动数据 |
| cycle_003 | 82.821 ms | 0.004517 rad | 有足够运动数据 |
| cycle_004 | 无法拟合 | — | 有效近接触反馈不足，保留记录 |

原始证据与无法拟合项在 `outputs/execution_delay_window_20261111/fit_current90.json`。3条有效轨迹不能支持未来P95/P99或“真实延迟恒为83 ms”的结论；新范围仅生成 `shadow_current90_diagnostic.yaml` 观察副本，没有替换运行参数。旧14次与新3次的轨迹、速度和条件不同，不能把两批差异直接归因于主机变化。

辨识先用已知85 ms的合成移位检查正负号；拟合不外推指令，不用异步角度差分估计加速度。静止数据、时序混乱、拟合搜索触边、时间基准不一致或近接触样本不足均保留为不可辨识。生成范围时不会按夹持是否成功筛样本，也不会悄悄丢弃高残差拟合来缩窄范围。

## 离线验证结果

1. 新增28项测试覆盖残余符号、仅扣一次提前量、区间边界、位置误差预算、重新计算接入、零跟随、观察模式、绑定失效、实际发送起点、配置哈希、原始文件哈希、低质量拟合拒绝和已知延迟恢复。
2. 相关回归：**525 passed，24 skipped**，记录为 `outputs/execution_delay_window_20261111/regression.txt`；外部等待位更新后再次回归仍为525通过、24跳过，见 `regression_after_external_site_update.txt`。跳过项是原有不支持的短跟随/闭爪组合。
3. 一项历史用例的两个参数组合原本因读取更新后的现场带向而失败；已在修改前配置加载器上复现。用例现明确绑定历史观测所用的带向，没有修改现场带向或放宽断言。
4. 最近一批4条历史已交付参考均通过条件性区间检查；这既不是4次抓取成功，也不是4条都成功执行。第4条没有足够运动数据做延迟辨识，但它的已规划参考仍能单独接受窗口检查，两类记录的分母不能混用。
5. 用同一份最新真实冻结输入，观察模式和实验模式分别跑完整生产规划，两者均为 `plan_ready`，且保留了发送时间余量。原几何检查各52个样本，最大TCP参考位置误差约0.024 mm。这是模型回放误差，不是实物定位精度或真机发送结果。
6. 合成解析边界案例显示：名义坐标−0.199 m或+0.379 m虽在原区间内，但在上述残余范围下越界；区间内部低速案例通过，1 m/s案例因超过5 mm试验位置预算被拒绝。见 `analytic_boundary_cases.json`，这些都没有计为实物样本。

所有回放、辨识和配置检查均为相机连接0、CAN连接0、发送命令0。

## 使用工具

在工程根目录显式使用源码，工具本身不执行抓取：

```bash
PYTHONPATH=src/nero_core OPENBLAS_NUM_THREADS=1 python3 tools/execution_delay_experiment.py fit \
  --run runs/hardware_tracked_20261111_165216 \
  --advance-s 0.09 --window-start-s 0.75 --window-end-s 1.20 \
  --output runs/paper_delay_pilot/fit.json
```

从已有14次分析生成范围的语法示例；条件标签是操作者声明，不是程序自动证明该主机、负载和运动条件一致：

```bash
PYTHONPATH=src/nero_core python3 tools/execution_delay_experiment.py profile \
  --analysis runs/diagnostics/grasp_delay_20261111_150629/delay_analysis.json \
  --output runs/paper_delay_pilot/profile.json \
  --condition-id existing_host_v121_pilot \
  --margin-s 0.005 --maximum-fit-rms-rad 0.01
```

生成独立观察配置，不覆盖现场文件：

```bash
PYTHONPATH=src/nero_core python3 tools/execution_delay_experiment.py config \
  --base-config src/nero_bringup/config/two_second.hardware.tracked_freeze.yaml \
  --profile runs/paper_delay_pilot/profile.json --mode shadow \
  --maximum-relative-error-m 0.005 --output runs/paper_delay_pilot/shadow.yaml
```

若创建规划约束实验副本，应另用 `--mode experimental` 和新输出路径。输出文件已存在则拒绝覆盖。配置、标定、示教路径会解析到原文件的绝对路径；延迟范围文件用SHA256固定，主运行来源清单也包含该文件哈希。

```bash
PYTHONPATH=src/nero_core python3 tools/execution_delay_experiment.py audit \
  --config runs/paper_delay_pilot/shadow.yaml \
  --run runs/hardware_tracked_20261111_165216 \
  --output runs/paper_delay_pilot/audit.json
```

`audit` 只重建已交付参考做条件性检查，不重新执行旧日志。原始曝光、目标身份和规划提交必须匹配；没有交付计划的周期和缺失输入也会留行。

## 尚不能宣称的内容与下一步

- 反馈时间是主机接收时间。等效滞后包含控制器、运动响应和反馈回传；未拆分纯物理延迟。用它作为实际运动偏移的代理仍需同步视觉或设备采样时间戳校验。
- 近接触常数滞后不代表整个接近/减速阶段和所有关节均为同样时延。此版没有认证连续不确定碰撞管，也没有在线检测所有超出延迟范围的物理响应；报告明确标记 `uncertain_collision_tube_certified: false`。
- 当前现场配置是零独立等速跟随，闭爪后进入减速。本检查只覆盖同步/跟随参考区间，不据此保证夹爪闭合期间均有同速接触；夹爪物理闭合时间尚未辨识。
- 历史区间加试验余量不是硬件最坏情况上界，也没有未来覆盖概率保证。换主机、负载、固件、发送频率或运动条件后，需要重新收集并验证。
- 真实输入的两种模式都通过，当前并没有显示提高抓取成功率。正式实验要比较调优固定方案、现有测时方案及新窗口方案，并同时记录总投入、漏检/跳过、完整实物成功率和单位时间成功件数，不能通过少抓来制造更高成功率。

下一步先以观察模式对齐更多完整周期、逐件录像和真实带速，再锁定有依据的时延范围及误差预算，最后开展独立实机对照。本轮功能没有自动部署或更改现场启动方式。
