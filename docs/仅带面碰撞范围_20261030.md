# 真机两秒策略：环境碰撞仅使用实测带面点云

用户于 2026-10-30 明确确认此前非带面场景残留为噪声，并要求只考虑传送带点云。本次将其作为显式环境范围配置接入原规划与执行路径，不再停留于上一轮的孤立保存姿态对照。没有启动相机、机械臂或 CAN，没有发送真机命令。


源码与安装目录均已更新，原先使用该文件的 `two_second_pick` 启动命令会读到新范围。运行开始只增加一行简短提示：

模板及没有设置该字段的其他配置仍使用 `observed_scene`。未知值、null 或 `ignore_all` 均会在设备导入之前被拒绝；没有“关闭所有碰撞”的选项。

## 点云如何选择

新模块 `nero_core/two_second/belt_collision_scene.py` 从**本次选定曝光**已经反投影得到的 `detection.scene_points` 中选择：

1. 坐标有限，位于实测带面的 XY 边界内；存在可见绿色轮廓推算的 `scene_bounds_xy_m` 时沿用该范围，否则使用原 `bounds_xy_m`。
2. 相对实测带面法向的距离绝对值小于 5 mm。这里复用 `BeltSurface.from_frame` 原有的支撑带定义，没有增加新的夹持阈值。
3. 沿用原真实点体素代表及不超过 4 mm 的覆盖误差约束，不生成平面点、不填洞、不生成平均坐标；保留输入索引及原生像素映射。

非带面场景点不会进入环境碰撞树，也不会参与载物点云与环境的距离判断。此选择不重新生成整图 XYZ、HSV 或 RGB 投影；不执行与此范围无关的全场景噪声、自体点和背景过滤链。点云与 KD 树只在本次任务场景安装时建立一次，绑定曝光帧、目标、时钟代次、标定、场景版本；后续候选和载物路径使用同一来源，机器人几何仍按每个实际检查状态更新。

没有有效带面点、边界/刚体变换无效、像素索引不一致、帧序号或时钟代次不匹配时拒绝安装，不以空环境代替。目标点云、OBB 抓姿和卡尔曼速度不受环境范围选择影响。

## 保留的检查和覆盖边界

原 `RobotModel.check_state` 仍正常检查环境，碰撞几何和余量未修改；自碰撞、关节范围、工作区、带面下穿、工件提前接触、夹持反馈、载物估计、q/v/a、取消与旧结果隔离、发送截止、发送所有权均保留。接近、闭合跟随、抬升、搬运、张爪和返回共用本次安装的带面环境。

范围是**相机可见的实际带面原生点云**，并非传送带完整实体模型；未建模边框、支架、遮挡空间或其他场景障碍。该设置也没有为 MuJoCo 添加真实相机点云碰撞：仿真现有的原生接触检查保持原样。
