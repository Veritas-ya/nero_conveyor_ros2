# 动态目标与完整轨迹时刻

目标位置、抓姿和轨迹时间需要共同满足：曝光时刻的抓姿，按测得速度预测到接触时刻；接触时刻位于工件允许的抓取区间；从实际关节反馈到该接触姿态的完整轨迹、跟随闭合及抬升经过原认证。几何 ETA 和网络候选都是提案，不是可行路径证明。

本轮在 `full_preplanned` 中调整：

- 可用视觉预测具有未来抓取窗口时，允许工件尚在窗口上游就启动完整规划；普通短期预览预测点不再充当完整规划的目标选择门槛。旧控制模式行为不变。
- 用观测时刻和实测速度预测抓姿。初始接触时刻落在当前可抓取窗口内，并扣除既有截止余量；如果几何 ETA 超出窗口，会在允许窗口内尝试，而不把 ETA 当作不可达证明。如果连既有最短接近时间都放不下，则记录失败并固定保持。
- 规划请求携带同一策略时钟下的最早和最晚接触时间。轨迹持续时间调整及预执行的交付时间修正仍须在该窗口内；每次变化保留原完整几何、速度、闭合和抬升认证。运行中的未来轨迹更新使用新观测对应的窗口，不复用旧窗口。
- 完整规划尚未交付时，如果即便立刻交付也无法在窗口内容纳原有最短接近时间和余量，取消后台搜索并给出 `full_pick_window_expired_during_planning`；不会把超时当成数学上无解。
- 离线候选重试也识别 `no completely certified full pick`，但取消、反馈错误和交付截止仍不伪装成几何失败。每次候选切换重新进行目标和时间绑定。

测试包括：上游目标可启动、预览位置不替代接触窗口、ETA 超出时仍提交窗口内接触、接触超窗不运行昂贵认证、完整规划在窗口内正常通过、交付时间修正不能越界、过窗取消以及原重规划/闭合回归。这些是离线和受控模型验证，不代表真实抓取或每个物体都能成功。

## 仍未完成

现有网络物理诊断一次只处理一个目标，尚无多目标队列、自动为每个工件建立和结束完整执行任务的接线；更不能保证超出物理工作区的物件一定抓到。现有视觉诊断的候选初筛仍有固定偏好拦截位置，原有 `measured_candidate_motion_plan` 的候选逐个运动估计尚未连进这个仿真入口。需继续接入，避免初筛错过其他时刻可行的抓姿；完整 ROS/物理执行及料箱闭环仍未完成。

本轮尝试启动 MuJoCo + GraspGen-X 实际验证时，独立 GPU Python 进程在模型启动阶段卡住，未进入实际推理或规划；发送终止信号后进程仍未退出，不能把此前运行的记录当成本次验证。核心离线测试和 ROS 构建结果另见本轮交付说明。外部模型和 CUDA 环境可用后，应重新运行 `tools/probe_measured_network_scene.py`，记录实际到达、候选和窗口时刻，再验证物理控制。
