# 可见包围盒中心 + GraspGen-X 方向（仿真对照）

这个模式仅在 `tools/probe_measured_network_scene.py` 通过 `--grasp-position-mode visible_bbox_center` 显式启用。默认 `network` 仍保持网络原始位置和方向。二者都使用 `full_preplanned`；此工具只读仿真，不发送机械臂或夹爪命令。

1. 使用同一曝光帧的目标掩码和深度，得到世界坐标的可见目标点集。仿真带面与世界 XY 对齐；取点集 XYZ 最小值和最大值的中点，即**世界轴对齐包围盒中心**。不做 PCA、隐藏面补全或真实中心推测。
2. GraspGen-X 正常推理，保留每个候选的网络旋转矩阵。根据仿真夹爪 `T_canonical_ee_site` 的完整刚体变换，平移候选使它的**仿真 TCP（ee_site）**落在包围盒中心。之后它仍是完整六维位姿，而非只有三个欧拉角。
3. 重新执行原有张开夹爪/带面间隙、目标点云、IK 和候选检查；网络未对平移后的新位置重新评分，原分数仅用于确定搜索次序。记录原始网络位姿、原评分、平移后的 TCP、帧时间和包围盒中心。
4. 选中候选与同一帧、目标身份绑定；之后沿用原算法基于后续目标点云中位数的实测平移跟踪，并使用 Nero7 卡尔曼速度预测。`full_preplanned` 根据新姿态重新规划并做完整认证，保留 100 ms 的仿真参考提前量和认证。

可见点包围盒中心不一定是完整工件的中心，更不保证 TCP 是可靠夹持点。仿真 TCP 和带面不是现场标定；中心也可能位于中空物件的空腔。原网络评分对应移动前的位置；比较两个方案的成功率前必须进行新的评分和物理夹持验证。

## 离线同输入对照

复用一帧已有的 2174 个渲染深度目标点、同一组 512 个已保存的网络姿态及其分数，检查两种位置方式的刚体格式、TCP 高度和张开手指与带面间隙。两个方向对称形式合计 1024 个方向：

| 指标 | 网络原始位置 | 可见包围盒中心 |
| --- | ---: | ---: |
| 通过上述几何初检的方向数 | 196 | 182 |
| 对应的不同网络姿态数 | 98 | 91 |
| 因手指/带面间隙不满足拒绝的方向数 | 808 | 842 |
| 因 TCP 高度不足拒绝的方向数 | 20 | 0 |

这**只比较几何初检**，没有运行 IK、完整路径、物理抓取或重新评分；同一对象的单次对照也不能证明中心方式的整体成功率。完整参数、输入文件哈希和数值在 [几何对照记录](evidence_bbox_20261028/saved_geometric_comparison.json)。

## 实际网络和完整规划诊断

在单次 MuJoCo RGB-D + 实际 GraspGen-X 网络运行中，候选位置按此模式改变；Nero7 测速约 0.0987 m/s，网络生成 512 个姿态，2 个通过当批初筛。选中的第 15 号候选产生了完整规划结果：路径及后续轨迹的规划认证通过，工作耗时 4.18 秒墙钟，策略时钟收到结果为 2.10 秒、计划起始为 2.19 秒。两种时钟不能相减。网络推理 1.16 秒、候选筛选 0.87 秒、场景过滤 3.21 秒；场景过滤与网络准备并行，不可简单相加。模型加载/预热另计。

此工具在接到完整规划结果时停止，未发送任何仿真动作；**没有完成执行前的实际动态场景/反馈验证，也未验证夹持、抬升或投放**。记录见 [实际网络及规划](evidence_bbox_20261028/live_center_full_plan.json)。与保存帧几何对照并非同一次输入，也无法据此断言性能或成功率提升。

## 运行

需要独立 CUDA Python 和 GraspGen-X 权重，算法导入来自新项目。以下在 Ubuntu 图形桌面终端运行，可显示实时点云及选中姿态；结束后窗口保持，关闭它退出。

```bash
cd /home/ubuntu22/nero_conveyor_ros2
export PYTHONPATH="$PWD/src/nero_core:$PWD/src/nero_bringup"
export NERO_GRASPGENX_CHECKPOINT_DIR=/absolute/path/to/checkpoints/release
export MUJOCO_GL=egl OPENBLAS_NUM_THREADS=1
/path/to/cuda-python tools/probe_measured_network_scene.py \
  --grasp-position-mode visible_bbox_center --viewer --hold-viewer --seconds 35 \
  --output /tmp/nero-bbox-center-result.json --capture-output /tmp/nero-bbox-center-frame.npz
```

去掉 `--viewer --hold-viewer` 可以无窗口运行。按保存数据重做几何比较：

```bash
PYTHONPATH=src/nero_core python tools/compare_visible_bbox_grasp.py --output /tmp/nero-bbox-comparison.json
```

## 带面约束 OBB 中心（实验模式）

`--grasp-position-mode visible_obb_center` 在同一次曝光的目标点云上，先在仿真世界 XY 平面求最小面积有向矩形，再沿世界 Z 求高度，得到带面约束的 OBB。使用其中心作为 TCP 位置，保留 GraspGen-X 的网络方向；原评分仅属于平移前姿态，不代表新姿态的评分。转换之后仍执行原来的夹爪间隙、IK 和完整轨迹检查，使用 `full_preplanned`。世界 Z 是本仿真带面法向，真实设备需要用标定的带面坐标系转换，不能直接照搬。

这只是可见表面的盒子，遮挡、缺失表面、噪声和异常点会影响中心和方向；它不是完整物体的真实几何中心。近圆形或近正方形物体的 OBB 朝向不稳定，因此此模式不使用 OBB 方向替代网络方向。二维点退化无法形成盒子时直接拒绝，不生成伪造抓姿。

```bash
cd /home/ubuntu22/nero_conveyor_ros2
export PYTHONPATH=src/nero_core:src/nero_bringup
export NERO_GRASPGENX_CHECKPOINT_DIR=/实际路径/GraspGenX/checkpoints/release
MUJOCO_GL=egl python tools/probe_measured_network_scene.py \
  --grasp-position-mode visible_obb_center --seconds 35 \
  --viewer --hold-viewer --output /tmp/nero-obb.json
```

此入口是只读诊断：视觉、网络和 `full_preplanned` 的规划尝试被调用，但不会发送关节或夹爪运动。视觉网络与经过认证轨迹的物理执行链仍未接通，不能据此宣称 OBB 已经完成夹持。`docs/evidence_bbox_20261028/obb_comparison.json` 是同一保存输入下的几何筛选对照，不包含 IK、全路径或物理接触；`live_obb.json` 记录实时仿真尝试。
