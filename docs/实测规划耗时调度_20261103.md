# 根据实测耗时调度抓取

现场配置改为 `planning_reserve_mode: measured`、`planning_reserve_s: 0.0`，不再为抓取规划固定预留 2.5 秒。这个 0 表示首轮没有历史估计，不表示计算无需时间。首次计算以当前时间和工件运动预测预约；候选完成全部认证时若发送时刻已过，不会平移或执行原轨迹，而是记录该候选实际耗时、重新预测目标位置并重新计算。后续候选及同进程后续物件使用已完成候选的实测耗时；轨迹交付后的线程调度、厂家准备与反馈读取如使预约过期，也记录实际耗时并重新计算。处理耗时估计只在本进程内保留，重启后重新测量，最多重试四轮且仍受原规划总预算限制。

当前模式在已有配置的最大上游冻结距离 0.35 m 处尽早冻结，给计算留空间，不使用固定时间反推冻结距离。目标仍使用同一帧观测和速度预测，轨迹每次重新计算、按新时间完成原有限值与几何检查；任何一次实际发送起点已过期都不会执行。实际交付可能受设备准备、实时调度或观测质量影响，无法保证每件都能及时完成。提前 0.1 秒发送、2 秒接入、0.3 秒闭爪跟随、夹持反馈、发送与到位检查仍存在，并非由此次请求取消。
