# 论文时序对照实验工具

工具入口是 `tools/paper_experiment.py`。它生成配置副本、登记试验、关联已有运行日志和导出统计，不连接相机或 CAN，不执行抓取、不重启运行进程，也不自动重置规划历史。

同输入A/B/C离线回放使用 `tools/paper_replay.py`。本轮实际结果及下一轮补测清单见[回放报告](论文离线回放与补测清单_20261106.md)。调参后固定预约与C在当前6帧上均为3帧规划就绪，尚不能宣称C优于固定预约。

## 历史冻结输入的同输入回放

该入口读取已有 `preview/target.npz` 和精确匹配的 `cycle_*/events.json`，重建一次实测带面，三组使用相同目标点云、抓姿、历史速度和曝光至提交的年龄。每组建立独立冷启动规划器，记录当前代码与输入哈希。它只回放规划层，未测试实际SDK准备、发送和完整抓取。

```bash
PYTHONPATH=src/nero_core OPENBLAS_NUM_THREADS=1 python3 tools/paper_replay.py \
  --session runs/paper_timing_pilot \
  --runs runs/hardware_fixed_freeze_20261106_105659 \
         runs/hardware_fixed_freeze_20261106_111545 \
  --output runs/paper_timing_replay_new
```

`--session` 指向本工具生成的独立配置目录；回放会明确使用每个历史事件中记录的预测速度，覆盖本次回放内的速度设置，并把该规则写入清单。不会改写配置文件。当前只支持存档足以重建的 `measured_belt_surface_only` 场景。

应先确定完整的输入选择规则，再运行回放；缺少冻结文件的运行也可传入，它会在A/B/C各保留一条 `input_rejected`。`planning_rejected` 是规划拒绝，`replay_error` 是回放工具错误；两者单独报告。输出目录必须不存在。三组相同输入哈希、每组结果和缺失项均保存，重复回放同一帧不能当成新增实物样本。工具不写入实物试验台账。

## 原功能与实验入口

没有 `timing_experiment` 字段的配置仍使用原有规划和交付逻辑。现场 YAML、示教文件、机器人限值、反馈检查、发送检查和碰撞范围没有修改。新增实验路径只有在配置副本显式声明该字段时启用。

| 组别 | 预约方式 | 规划或交付过期 | 目的 |
| --- | --- | --- | --- |
| A | 预实验选择的固定值 | 拒绝本次任务 | 基础对照 |
| B | 与 A 相同的固定值 | 在原限值和总预算内重新计算 | 重规划恢复的作用 |
| C | 实测规划与准备时间 | 与 B 相同的重试上限及总预算 | 实测预约的额外作用 |

A/B 不使用测时历史更新固定预约。B/C 的内层规划最多四轮，外层交付最多四次，且共用从外层规划起点计算的总预算。不能把两层上限解释为全程只有四条候选。非时间类失败、取消、起点改变等条件仍按原检查处理；不为实验放宽限值。

三组使用相同的平滑规划、候选检查和明确的固定观测冻结位置。A 的实验路径也完成共同的候选检查后判定时序，因此它是明确的实验基线，不应声称与原固定模式每个提前退出时刻都相同。

新增记录只在规划和交付阶段产生；没有给高频发送回调增加磁盘写入。已有 `execution_trace.npz` 用于事后读取实际 SDK 调用时刻。新增诊断记录失败不会替代运动判定。

## 创建独立试验目录

在项目根目录运行，并明确让本次 Python 使用源码。无需覆盖原安装目录或修改原启动配置。

```bash
cd /home/ubuntu22/nero_conveyor_ros2
PYTHONPATH=src/nero_core python3 tools/paper_experiment.py --help
```

以下是创建45次预实验计划的语法示例。`0.50` 秒只是待调整的预实验候选值，不是已验证的最佳固定预约。冻结距离和速度必须对应现场；不要用这些示例数字替代测量。

```bash
PYTHONPATH=src/nero_core python3 tools/paper_experiment.py prepare \
  --base-config src/nero_bringup/config/two_second.hardware.legacy_observed.yaml \
  --output runs/paper_timing_pilot \
  --fixed-reserve-s 0.50 \
  --freeze-position-m 0.50 \
  --fixed-speed-m-s 0.40 \
  --freeze-source tracked \
  --objects W01 W02 W03 --groups A B C --repeats 5 --phase pilot \
  --reservation-note '预实验候选值0.50秒，正式选值前另行比较' \
  --history-rule '本批次每次由独立新进程冷启动，不使用未记录的预热'
```

省略 `--fixed-speed-m-s` 时继承原配置的速度来源；它不能改变配置的速度上限。使用现有单帧冻结入口时，创建计划应选择 `--freeze-source single_exposure_native_depth`，并使用原入口要求的固定速度。导入日志时会核对实际使用的采集入口。

生成目录包含：

- `configs/A.yaml`、`B.yaml`、`C.yaml`：独立副本，原配置不变。
- `manifest.json`：基准配置、代码和标定哈希、方法定义、速度来源、示教哈希、历史规则和随机种子。
- `plan.csv`：随机化顺序；同一工件同一次摆放条件的 A/B/C 具有同一个 `pair_id`。
- `trials.sqlite3`：全部计划行初始均为 `not_started`，另存逐次操作的审计记录。

已有输出目录会被拒绝，不覆盖旧试验。相机和 TCP 标定、示教路径会解析为原配置对应的绝对路径，防止副本搬到新目录后指向不同文件。生成时只读检查配置和示教，不启动设备。

`history_rule` 是事先声明的现场操作规则，软件不替操作员执行重启。C 的日志会记录调度前规划和准备耗时历史；运行目录与周期号可追溯前序尝试。若要研究热启动，应在新批次明确预热次数、重启边界和实际执行记录，不能在失败后选择性清空历史。

## 检查实验配置

```bash
PYTHONPATH=src/nero_core python3 -m nero_core.two_second.main \
  --config runs/paper_timing_pilot/configs/A.yaml --check-config
```

对 B、C 同样检查。该命令不连接硬件。实验副本尚未在真机验证，创建计划或通过配置检查不代表能够抓取成功。

现场执行仍使用原来的受控启动方式，选择该试验对应的配置副本，并为运行保留独立输出目录。若从源码运行，使用与上面一致的 `PYTHONPATH=src/nero_core`；仅创建配置副本并不会更新旧安装包。不要把三组配置替换进原生产启动文件。

现有 `--count 1` 按**反馈成功周期**计数，失败恢复后可能继续等待下一件。它不是“一次实物试验”的计数器。本工具不改这个行为；每个投入工件单独登记，每个被接纳的目标按实际 `cycle_XXX` 关联，漏检也要留在人工记录中。

## 投入工件前登记

先查看 `plan.csv` 的下一行，再用对应编号登记。下例的 `P0001` 是计划编号，不代表固定属于 A 组；分组以计划为准。录像起点单位为秒，不是主机单调时间。

```bash
PYTHONPATH=src/nero_core python3 tools/paper_experiment.py begin \
  --session runs/paper_timing_pilot --trial P0001 \
  --video /absolute/path/batch01.mp4 --video-offset-s 12.5
```

状态变为 `pending`。录像文件允许稍后复制到约定位置，导出时检查路径是否存在并产生缺失提示。不能因为一次目标没有被视觉接纳，就不登记这次投入。

## 关联已有运行日志

```bash
PYTHONPATH=src/nero_core python3 tools/paper_experiment.py bind \
  --session runs/paper_timing_pilot --trial P0001 \
  --run /absolute/path/hardware_run --cycle 1
```

关联时核对配置、源文件及标定哈希，以及运行时实际速度输入、冻结位置、采集入口和示教文件。通过命令行覆盖了不同带速或示教、配置生成后被修改、组别不一致，都会拒绝关联。一次运行的同一周期不能重复用于两条试验，一条试验也不能绑定多个周期。

读取的证据包括每个规划轮次的预约量和耗时、准备阶段过期、接触与跟随结束位置、抓取窗口余量、实际首次拦截指令发送时刻、程序阶段和反馈报告。恢复动作的指令不会被误算为首次抓取发送。缺失数据留空，不填零。

运行采用现有事件格式，优先读取 `cycle_001/events.json` 和 `report.json`；中途异常但事件已刷新时，可从根目录 `events.jsonl` 中选择该周期。完整导入数据及证据文件哈希在导出结果中保留。相机时间和主机时间不直接相减；时差只在同次运行的主机单调时间域中计算。

## 核实实物结果

反馈周期完成不会自动改变 `pending`。成功必须由现场或录像确认夹起、正确投放和返回三项。

```bash
PYTHONPATH=src/nero_core python3 tools/paper_experiment.py finish \
  --session runs/paper_timing_pilot --trial P0001 --status success \
  --grasp 1 --place 1 --returned 1 \
  --measured-speed-m-s 0.398 --cycle-time-s 5.3 \
  --evidence-note '录像12.5秒开始，17.8秒确认返回，三阶段均核实'
```

这里的速度和时间也是填写格式示例，必须替换为实测值。`--cycle-time-s` 仅用于实物成功周期；失败可填写 `--termination-time-s`，两个口径不能混用。软件导出的规划提交至最后阶段时间单独命名，不能当作录像核实的完整周期时间。

漏检或规划拒绝没有实物夹起，不需要伪造后续阶段：

```bash
PYTHONPATH=src/nero_core python3 tools/paper_experiment.py finish \
  --session runs/paper_timing_pilot --trial P0002 --status failure \
  --reason missed_detection \
  --evidence-note '连续录像中该工件通过试验区，视觉未接纳'
```

没发生的阶段省略。空抓可填 `--grasp 0`，掉落、投放失败等按录像填写，缺项不自动变为成功。外部中断使用 `--status external_interruption` 并填写原因，单独计数。

已经结束的试验不能直接覆盖；核实后修正时重新执行 `finish` 并增加 `--correction-reason '具体修正原因'`。数据库会保留原结果和新结果。

## 导出与正式试验

```bash
PYTHONPATH=src/nero_core python3 tools/paper_experiment.py status \
  --session runs/paper_timing_pilot
PYTHONPATH=src/nero_core python3 tools/paper_experiment.py export \
  --session runs/paper_timing_pilot --output runs/paper_timing_pilot_export01
```

导出包含：

- `trials.csv`：计划、实物结果、录像定位、独立测速、实物周期时间及程序时间指标，可用 Excel 打开。
- `program_evidence.json`：按试验编号保留全部已导入程序证据，不自动推断实物成功。
- `audit.json`：登记、关联、结果判定与改判历史。
- `summary.json`：各组和各工件的成功率、Wilson 区间、配对差异及不一致对数、精确 McNemar 检验，以及记录缺失提示。

只有已明确成功或失败的记录进入对应分母，待开始和待核实单列；外部中断单列。规划耗时包含已关联失败尝试，输出中位数、线性插值95分位和最大值。小样本分位数不是实时保证，重复工件及共享历史可能引入相关性，检验不能单独证明创新。

正式采集时另建 `--phase formal` 的目录，不覆盖预实验或混入预实验数据。建议计划：

| 实验 | 参数变化 | 次数 |
| --- | --- | --- |
| 预实验 | 3种 × A/B/C各5次 | 45 |
| E1主结果 | `--groups C`，15种 × 每种20次 | 300 |
| E2方法对照 | `--groups A B C`，3种 × 每组每种20次 | 180 |
| E3带速变化 | 每个带速单独建目录，`--groups C`，3种 × 每种10次，0.20与0.30 m/s | 60 |

E2从旧初稿的两组120次扩为三组180次；全部正式计划合计540次。旧 Excel 的 E2预填行不能直接代表新增的三组排程，以本工具新生成的 `plan.csv` 为准。固定预约先用独立预实验选定，三组保持相同摆放和观察条件，按计划保留全部失败，不达到某个成功比例后提前停止。

## 软件验证范围

新增测试覆盖三组调度分离、同一曝光重新预测和几何检查、交付过期、共享总预算、取消、非时间失败、记录异常隔离，以及试验分母、配对、来源核对、实物判定和改判审计。原抓取、恢复、示教与单帧冻结回归使用假设备和离线数据。软件测试和配置检查不能替代实机预实验或作为论文成功率。
