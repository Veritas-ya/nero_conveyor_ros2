# 搬运平滑与到位张爪（2026-11-14）

## 现场记录定位

本轮读取 `direct_drop_20261114_190318`、`190346`、`190644`，没有连接相机、CAN 或发送真机指令。

三次搬运预规划都已在抓取减速结束之前完成。结束后的实际载物复核分别约 0.208、0.240、0.229 秒，所以此处仍有真实的等待。原有 `internal_planning_stops: 0` 仅表示途中没有临时规划等待，不能表示轨迹内部没有减速到零。

原搬运由抬升和直接投放连接；直接投放又含 3、4、4 个 RRT 路径点。每条相邻点轨迹都采用零速度、零加速度端点，因而即使使用一个发送线程，仍会在抬升终点及中间绕行点停车。

投放端还有 0.1 秒到位停留。上述三次发送张爪指令在 `stage_finished` 后约 6～7 毫秒发生，但 `stage_finished` 本身已经包含该停留；张爪后的约 0.41 秒还包含实际开爪和开口反馈确认。

## 本次修改

- 实验直接投放路径：在内部转折点加入局部五次多项式过渡，保持位置、速度、加速度连续，途经点本身保持不变。抬升连接使用进入方向的切线，且局部修改不跨过下一个受保护路径点。整条搬运起点和投放终点仍为零速度、零加速度。
- 修改后的曲线重新检查关节位置及速度、加速度的多项式极值、jerk，以及载物、带面、框沿和机器人几何。需要时统一延长时间；局部过渡无法通过时记录原因并保留原已认证路径。没有关闭碰撞检查或增加物理上限。
- 到投放点后，以终点指令已发出、轨迹结束时刻之后的有效关节反馈、原有到位误差范围为依据，首次确认即结束搬运并进入张爪，不再额外等待 0.1 秒。等待位及其他动作的到位停留不变。
- 张爪指令先于回程任务提交。张爪后的原有开口确认仍保留，确认后才开始返回。
- 新增 `drop_arrival_confirmed` 事件与 `corner_blend` 诊断，可区分到位、实际张爪发送、路径平滑是否采用。

平滑当前作用于 `--experimental-direct-drop-guard` 的直接投放路线，不改写录制的示教曲线。默认启用；`direct_drop_blend_enabled: false` 可用于同条件离线对照。
