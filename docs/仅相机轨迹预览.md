# 仅相机轨迹预览

该入口只打开 RGB-D 相机，不创建 CAN 连接，不发送机械臂或夹爪命令。它使用现场相机标定、工件点云、OBB 候选、传送带速度和真机平滑轨迹规划器计算模型轨迹，渲染在同一曝光的点云上。

在终端运行：

```bash
cd /home/ubuntu22/nero_conveyor_ros2
source /opt/ros/humble/setup.bash
source install/setup.bash
OPENBLAS_NUM_THREADS=1 ros2 run nero_core camera_grasp_view \
  --config /home/ubuntu22/nero_conveyor_ros2/install/nero_bringup/share/nero_bringup/config/two_second.hardware.legacy_observed.yaml \
  --trajectory-preview --fixed-belt-speed-m-s 0.1727 \
  --output "/home/ubuntu22/nero_conveyor_ros2/runs/camera_path_preview_$(date +%Y%m%d_%H%M%S)"
```

相机应只被一个程序使用；退出真实抓取程序后再启动此窗口。等待带面初始化，将工件从上游送入画面。上例明确设为 17.27 cm/s 固定带速，视觉跟踪用于身份关联；省略带速选项则沿用配置文件的速度来源。拖动可旋转点云，滚轮缩放，空格重新等待，Esc 关闭。

黄色线是机器人模型 TCP 轨迹，绿色点是起点，白色点和夹爪是预测接触位姿；青色点是曝光时的工件，紫色点是推算的接触时工件位置，灰色是同帧场景点云。轨迹及场景冻结在相同曝光，左侧实时画面仍会更新。预览任务正在运行或规划失败时，窗口上方会给出状态，失败不画虚构轨迹。

轨迹起始关节是假设机械臂在配置等待位，并没有读取实际关节。工件检测未使用实时机器人自体过滤。规划使用真实单调时钟和现场配置的规划时序策略；`measured` 模式会根据实测耗时重新计算接触时间及路径。单个预览实例复用模型和测时估计，每次仍安装对应曝光的实测场景并认证轨迹，另有20秒实际计算上限。截止余量包含规划后的 FK 采样和场景准备，负值会单独标为已错过。输入压缩及路径文件由单独线程存档，关闭时等待写完；界面轮询与真正发送的耗时未认证，不能声称实机可执行。

2026-11-04当前策略：`rotate_first_s: 0.0`，边转边接近1.2秒（`prealign_orientation_s: 1.2`、`synchronized_join_candidates_s: [1.2]`），跟随0.1秒、减速0.4秒、发送提前量30ms；夹持反馈连续确认0.2秒，在跟随及减速期间持续检查。等待位从此前抬高50mm的位置沿标定带向上游移动100mm，高度和姿态保持不变。相机预览和十次记录入口均读取同一份现场配置并调用真机规划器。真实规划时钟、模型复用及后台存档保留。已经打开的旧窗口不会自动更新；使用上面的现场配置路径重新启动后才加载新策略，历史测试存档保持原参数。

`paths/` 下每条路径包含 `.npz`（时间、七轴关节、TCP 轨迹、同帧 RGB-D、场景点云、目标点云和接触预测）及 `.json`（速度来源、模型假设、曝光元数据、耗时及候选拒绝原因）。关闭窗口后 `session.json` 记录设备连接和命令数量。

记录十个独立目标可运行下面命令；同一目标的多个候选仍只计一次。这个入口的带速单位为 **cm/s**：

```bash
OPENBLAS_NUM_THREADS=1 PYTHONPATH=/home/ubuntu22/nero_conveyor_ros2/src/nero_core \
python3 /home/ubuntu22/nero_conveyor_ros2/tools/record_camera_planning.py \
  --config /home/ubuntu22/nero_conveyor_ros2/install/nero_bringup/share/nero_bringup/config/two_second.hardware.legacy_observed.yaml \
  --belt-speed-cm-s 17.27 --attempts 10 \
  --output "/home/ubuntu22/nero_conveyor_ros2/runs/camera_planning_10_$(date +%Y%m%d_%H%M%S)"
```

`summary.json` 的 `completed_attempts` 为已结束的规划次数；`complete=true` 还要求后台存档已结束。`archive_failures` 和逐次 `evidence_status` / `path_archive_status` 单独报告存档故障，不能算成规划失败。新记录保留原始 RGB-D、实际缓存的带面平面、场景点和目标跟踪位置，便于重放。
