# 仿真等待位转换为真机候选（2026-10-31）

只做离线换算、回放和配置检查；没有连接或控制设备。旧真机配置保留，候选配置单独存放，以免原有启动命令在没有现场核验时自动回位到新姿态。

## 原始仿真位姿

`runs/planning_alignment_20261031/simulation_final.json` 中，使用的仿真等待关节角（J1 至 J7，度）为 `[126.8276, -37.0495, 116.6375, 101.9438, 64.8287, 44.8353, 52.7474]`。仿真 TCP 世界坐标为 `[0.040508, -0.000242, 0.699959]` m，仿真带面高度约 0.5 m，即基本位于仿真带面中心上方 0.2 m。

不能直接将仿真世界坐标当作真机基座坐标。相同关节角输入真机名义模型时，TCP 为 `[0.040508, 0.339758, 0.099959]` m（机器人基座系），其在历史观测带面上的投影位于带宽边界以外约 0.282 m。因此仅复制关节角也不等于复制工件相对位置。

## 相对传送带换算

以历史保存的 `record_20261030_232939` 第 1 帧、现有深度到基座标定拟合带面及带宽，取带宽中点；沿运动方向取配置的抓取区间中点 `0.04 m`，沿带面法线取高度 `0.20 m`。将仿真夹爪姿态（TCP x 轴沿带速方向、z 轴朝向带面）旋转到拟合带面坐标。真机名义 TCP 目标：

- 基座坐标 `[X, Y, Z] = [-0.371010, -0.069310, 0.082534]` m；Z 是基座高度，距拟合带面 0.2 m。
- 基座系 TCP 旋转矩阵记录在 `runs/planning_alignment_20261031_wait_candidate/report.json`。不要把仿真世界欧拉角直接复制到真机示教器；示教器可能使用不同法兰/TCP 及欧拉角约定。
- 按现有名义 TCP 和机器人模型求得的候选关节角（度）：**`[-36.3190, 66.0301, 89.6737, 95.5756, -69.2308, -35.7488, 83.9229]`**；精确弧度值保存在候选配置 `src/nero_bringup/config/two_second.hardware.sim_aligned_wait_candidate.yaml` 的 `standby_joint_rad`。
- 这是多解逆运动学中的一个解；在此 TCP 位姿下，数值优化了最小模型关节边界余量，得到约 0.0861 rad。它不是针对真实路径和现场障碍的最优解。

该换算依赖单个历史画面的带面和边界、当时的相机标定、带速方向、配置抓取区间和模型名义 TCP。另一帧 301 的拟合带宽中点相较第 1 帧约差 0.43 mm，但两帧同属一次采集，不能证明当前现场未移动。

## 验证与边界

- 真机模型上，候选通过关节范围及静态自碰撞；从原配置等待位到候选位作 401 个等间距关节插值点，模型自碰撞、工作区和历史拟合带面检查通过。这不是厂家 `move_j` 的实际轨迹证明；历史带面点云不包含完整护栏和周边设施。
- 在保存的真实帧 271、301 上，以旧配置等待位假定为拍摄时的机械臂状态作自体过滤，再以候选等待位作为假定规划起点，分别在约 0.97、1.03 s 生成轨迹。两次均为首候选，使用固定带速 0.0595 m/s；输入状态均为假设，未使用实时关节反馈或发送。结果分别见 `runs/planning_alignment_20261031_wait_candidate/frame271.json`、`frame301.json`。不同等待位产生不同轨迹，时间不能当作严格的相同输入算法 A/B 测试。
- 已通过 ROS 构建与候选配置 `--check-config`。原启动命令仍指向旧的 `two_second.hardware.legacy_observed.yaml`，不会使用此候选；使用候选配置执行抓取时，程序可能自动驱动机械臂回等待位。启动前需要用当前相机画面和实时机器人状态核对带面、夹爪、现场障碍和回位路线。
