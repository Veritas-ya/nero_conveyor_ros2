# 动态抓取物理仿真

本入口迁自旧工程 `experiments/continuous_intercept_sim`，使用新工程内的 MuJoCo 场景、生产策略和完整规划器。物理模拟与规划在独立线程推进，规划时传送带继续运动；执行器按实际应用时刻采样已认证轨迹。原候选检查、时间、速度、加速度、反馈和闭合门控未修改。代码来源及 SHA-256 见 `simulation_migration/source_hashes.json`。入口 `run.py` 只调整了导入共享辅助函数及源码快照路径，使其能从新工作区和已安装包运行；原工程目录不参与运行。

这是**模拟历史观测和物体目录抓姿**的物理诊断，不运行实际相机、Nero7 测速或 GraspGen-X 网络，也不连接任何设备。仿真可以检查双指接触、重力、摩擦、抬升、物料箱投放和返回；策略的闭合命令、模拟器的 GRASPED 状态、独立夹持抬升和入框评分应分别理解。`completed` 表示运行进程正常结束，不表示抓取成功。

## ROS 2 无窗口

在有 ROS 2 Humble 及 `requirements.txt` 依赖的 Python 3.10 环境：

```bash
cd /home/ubuntu22/nero_conveyor_ros2
source /opt/ros/humble/setup.bash
colcon build
source install/setup.bash
ros2 launch nero_bringup physics.launch.py output:=/tmp/nero-physics-run-01
```

输出路径必须不存在；每次更换路径。默认 continuous / full_preplanned、种子 1543、类别 0、带速 0.04 m/s、55 秒、从 x=-1.28 m 上游上料、接近时间 3 秒、计算预算 3 秒、继续投放及返回（未成功时会记录失败）。可覆盖 `seconds`、`belt_speed`、`seed`、`category_id`、`spawn_x`、`minimum_approach_s` 和 `compute_budget_s`。这些是离线开发输入，不是实机参数或通过率验收。launch 仅启动仿真进程，当前 ROS 各算法节点与仿真仍未接线。

## 桌面实时窗口

在本机 Ubuntu 图形桌面的终端运行，先 source 上面的 ROS 环境，然后：

```bash
MUJOCO_GL=glfw OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
ros2 run nero_core physics_sim --mode continuous --planning-mode full_preplanned \
  --seed 1543 --category-id 0 --belt-speed 0.04 --spawn-x -1.28 \
  --minimum-approach-s 3 --full-plan-compute-budget-s 3 --seconds 55 \
  --through-bin --viewer --no-video --output /tmp/nero-physics-view-01
```

窗口只读显示模拟物理状态；关窗结束并保存记录。若提示需要 DISPLAY，请从登录图形桌面的终端运行。此会话没有 DISPLAY，本轮没有验证窗口。若系统 GL 驱动不兼容，可在图形桌面命令前设置 `LIBGL_ALWAYS_SOFTWARE=1 __GLX_VENDOR_LIBRARY_NAME=mesa`。

目录 `continuous/summary.json` 是运行与独立评分，`planning_results.json`、`full_pick_dispatch.json`、`physical_trace.npz` 和事件记录分别保存规划、实际应用和物理反馈。原程序另外保存源码哈希与快照；可以检查 `comparison.json` 的 `source_changed_during_run`。本入口现在默认请求仅仿真的 100 ms 命令参考提前并重新认证；设置 `command_advance_s:=0`（launch）或 `--simulation-command-advance-s 0`（命令行）恢复名义曲线。此提前不等于测得的响应模型，见 [提前100毫秒仿真](提前100毫秒仿真.md)。可通过 `--joint-response-model` 显式指定自己安装的 `simulation_only` 模型，并保留原完整认证；历史模型不能用来宣称实机效果。响应补偿和未来接续的同时运行仍有旧实现限制。

## 本次验证

以默认输入运行 18 秒：等待 → 接近 → 跟踪下降 → 发出闭合 → 恢复。10.58 秒原判定为 `predicted_close_window_left_certificate_tolerance`，实际最大抬升约 1.11 mm，独立夹持抬升未通过；未成功投放或返回。策略记录出现 GRASPED 不等于独立物理抬升成功。日志见 `simulation_migration/physical_run.log`，原始输出见 `../runs/physics_migration_20261027/continuous/summary.json`。没有加载响应补偿模型。

ROS launch 以 1 秒验证安装、启动和退出，处于等待阶段；未用于判断抓取。18 秒测试使用 MuJoCo 3.16.0，ROS 安装环境启动检查使用 MuJoCo 3.8.1，物理结果可能因版本不同而变化。物理适配、接续、接触评分、周期和响应诊断相关测试 **49 项通过**，约 4.56 秒。无窗口物理与单元测试均未连接真机。

默认出生位置沿用场景配置 `spawning.x=-1.28 m`；物理带面约为 x=-1.375 至 0.625 m，出生中心距上游边缘约 95 mm。默认 0.04 m/s 从出生点行至 x=0 m 约需 32 秒（这是匀速估算，实际受接触和动力学影响）。旧的 18 秒测试特意使用 x=-0.4 m，因此它的结果不能代表默认上游完整流程。
