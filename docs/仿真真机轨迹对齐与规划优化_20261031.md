# 仿真、真机轨迹条件对齐与规划提速（2026-10-31）

本次没有连接相机、CAN 或机械臂，也没有发送真机控制命令。现有运行的相机预览进程不会自动加载新版本，需要退出并重新启动才会使用更新后的代码。

## 规划提速

MuJoCo 在每个轨迹检查采样点都会生成接触距离；原实现逐个生成 Python 接触对象后寻找首个穿透。新实现对同一批距离按原顺序查找，存在穿透时才读取对应接触对象。没有减少检查点、调整碰撞距离、跳过检查或改变候选顺序。非原生的共享碰撞实现仍走原分支。

用保存的真实 RGB-D 第 271、301 帧，固定传送带速度 0.0595 m/s，假定机械臂处于配置等待关节角，交替进行各 3 次新旧规划对照，共 6 对。完整规划墙钟时间中位数由 **2.156 s 降到 1.649 s**，减少约 **0.507 s（23.5%）**。每对的候选通过/拒绝结果、选中抓姿以及轨迹上 501 个时刻的 7 轴位置、速度和加速度逐值一致。此为保存帧离线回放，不能作为现场检测、规划交付和控制延迟的保证；输入不含实时机械臂反馈。详细逐次结果和轨迹采样位于 `runs/planning_alignment_20261031/` 下的 `271_*` 和 `301_*` 文件。共享碰撞谓词提取后再次用 301 帧核对轨迹一致，结果见 `shared_collision_301.*`。

诊断脚本 `tools/replay_recorded_pick_plan.py` 的 `--legacy-contact-scan` 用于旧遍历基线，`--trajectory-npz` 保存对照采样，不控制设备。

## 同步的软件条件

`--hardware-conditions` 下，仿真接近与跟随段使用与真机相同的预测移动目标点云碰撞谓词、4 mm 距离和手指接触豁免。输入是仿真相机输出的冻结目标点云与预测速度，构建一次空间索引；不是工件真实网格。轨迹几何时间网格和 TCP 对参考轨迹误差门限也与真机代码共用；配置控制频率 100 Hz、几何采样 200 Hz。自碰撞/静态环境仍使用 MuJoCo 场景检查，闭合后的减速、载物和实际夹持仍使用仿真接触及物体状态验证，不能视为现场同等认证。

在此条件下，以模拟带速及预测固定速度 0.0595 m/s，随机工件 T-LESS 7、5，随机横向位置和初始偏转，两件均完成夹持、物体抬升、放入料框和返回，见 `runs/planning_alignment_20261031/simulation_final.{json,summary.json,log}`。该仿真使用仿真等待位、仅仿真重力补偿和未经过真机辨识的位置积分内环，因此只证明这个仿真配置内的物理流程；不是实机抓取成功率。规划末件耗时约 1.52 s（其中逆解/轨迹 0.73 s、几何检查 0.79 s，二者属于规划耗时组成，不能再加一次）。

## 等待位对照：仍需解决

新增 `--simulation-use-hardware-standby`，配合 `--hardware-conditions` 时仅在仿真初始化使用真机配置等待关节角；报告记录初始关节与配置之差。它不会让虚拟传送带、料框、相机和真机场地自动重合。

在相同随机种子下，仿真等待位与配置真机等待位最大关节差约 124°；模拟末端初始位置分别约 `[0.0405, -0.0002, 0.7000]` m 与 `[-0.4030, -0.3728, 0.5834]` m（MuJoCo 世界坐标）。改用配置关节角后，本例未生成可执行轨迹。首个候选在 2.38 s 检查到左手指与仿真传送带上游右侧护栏接触，穿透约 0.85 mm；第二候选第 6 轴位置越界，第三候选第 5 轴速度峰值约 2.041 rad/s，超过当前软件限制 2 rad/s；后续候选出现逆解未收敛，最后一个预算到期。记录见 `runs/planning_alignment_20261031/simulation_hardware_standby_diagnostic.json`。仿真碰撞诊断现在区分实际接触、TCP 高度、夹爪方向和关节余量，不再统称碰撞。

这暴露了条件不等价，但不能据此断言真机存在同样护栏碰撞：模型的现场坐标、带面、传送带护栏和料框还没有完整标定。要评估该等待位及不同候选，应使用实际相机外参和设备尺寸重建场景，并用不发控制命令的现场采集重放，随后按实测反馈评估起点和可行轨迹；不要把本仿真中的等待位直接写回真机。

可在项目目录重现真机等待角度的单件仿真（加 `--viewer` 可打开 MuJoCo 画面；这是离线仿真入口）：

```bash
cd /home/ubuntu22/nero_conveyor_ros2
PYTHONPATH=src/nero_core OPENBLAS_NUM_THREADS=1 MUJOCO_GL=egl \
  python3 tools/run_two_second_grasp.py --profile smooth \
  --hardware-conditions src/nero_bringup/config/two_second.hardware.legacy_observed.yaml \
  --simulation-use-hardware-standby --sim-gravity-compensation \
  --sim-arm-integral-time-s 0.5 --count 1 --seed 1543 \
  --belt-speed 0.0595 --fixed-prediction-speed-m-s 0.0595 \
  --category-ids 4 5 6 7 13 --spawn-yaw-range-deg 15 40 \
  --spawn-y-range -0.035 0.035 --bin-placement free_space --seconds 65 \
  --output runs/planning_alignment_20261031/standby_replay.json
```

## 尚未与现实等价的条件

- 相机渲染与真实 RGB-D 的遮挡、运动噪声、曝光、时钟和传输延迟不同；场景点云、机器人与带面标定误差仍需现场测量。
- 预测固定带速来源为人工输入，视觉速度和真实速度不是本轮测试对象。
- 模拟伺服、重力补偿、夹爪力值与厂家硬件环路未完成辨识；位置命令加速度和接触产生的实际物理加速度不是同一指标。
- 仿真时钟不等于现场单调时钟和 CAN 实际发送延迟；测试不能推出现场交付一定赶上工件。
- 模型使用 nominal TCP 而非本轮新测的 TCP；机械臂实际待机反馈、料框和障碍几何仍须确认。
